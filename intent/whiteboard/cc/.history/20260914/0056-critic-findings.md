# critic-shell review of the unlanded 0056 census column -- 2026-09-14

Archived by devbin-cc so the review outlives the session. It reviewed the uncommitted diff to `bin/.devbin/cmd/fleet` and `tests/unit/fleet.bats` -- now `0056-census-column-work.patch` beside this file -- against the shell rule library and the agnostic rules, and confirmed its main findings with small probes in the session's scratchpad. Line numbers in the original report referred to the patched file and are omitted here, because the change is not applied at HEAD.

## On the change

- **CRITICAL, IN-AG-NO-SILENT-001 -- `seam_committed` can print `committed` although git skipped seam files.** (1) An untracked `bin/.devbin/lib/fullcycle` -- Intentv2's case in 0056 -- reads DIRTY by default, and reads `committed` once `status.showUntrackedFiles=no` is set in the estate's repo or passed down from a caller's `git -c`; `_estate_git` clears only 3 of the 15 variables `git rev-parse --local-env-vars` lists. (2) A `.gitignore` containing `lib/` leaves `bin/devbin` and the manifest tracked and the lib never committed, and that also reads `committed`, because the tracked check asks only about the manifest. An inherited `GIT_COMMON_DIR` turns every estate `UNREADABLE`: the not-clean direction, but one wrong answer applied to every estate. Fix shape: `status --porcelain --untracked-files=all --ignored=matching -- <scope>`, classify `!!` lines as not tracked before the DIRTY test (and decide how ignored junk such as `.DS_Store` should read), and clear git's full local-environment list inside a subshell.
- **CRITICAL, IN-AG-HIGHLANDER-001 -- a second hand-written seam list, with the manifest path spelled again.** `vendored_scope` in `lib/install` owns devbin's half as git pathspecs, `source_commit_of` asks the same dirty question through it, `fleet` already sources `lib/install`, and `lib/helpers` defines `DEVBIN_MANIFEST_REL`. Build the pathspec from `vendored_scope "$root"` plus that constant, or the census goes on asking about the old paths the day the seam gains a directory.
- **CRITICAL, IN-AG-RED-CONTROL-001 -- the caveat's "so a clone gets these bytes" is a pass the column cannot fail.** It compares with the local HEAD only, so unpushed commits, a non-default branch or a worktree's branch all read `committed`. Say what is measured -- the seam matches this checkout's HEAD, and nothing about whether that commit is pushed -- and list `UNREADABLE` among the not-clean values.
- **CRITICAL, IN-AG-RED-CONTROL-001 -- the "does not track" arm ignores all of `bin/`**, so it cannot tell "the seam is tracked" from "the manifest is tracked" and stays green against case (2). No arm puts an untracked file under the seam, so case (1) is unguarded. Add a fixture that ignores only `lib/`, and one with an untracked lib file and `status.showUntrackedFiles=no`, and watch both fail against the current code before trusting them.

## Beside the change, in code it did not touch

- **CRITICAL, IN-SH-CODE-005 -- `scan` reads `< <(find_installs)` unchecked, and `find` discards its errors.** A probe with two roots and one unreadable directory under the first stopped the loop before the second root was scanned: exit 0, one install of two listed, no message. A directory vanishing mid-scan fails the same way, which could explain the unreproduced 13-to-12 drop the document's two-scan control was built for -- not proven. Keep `find`'s errors, record a failed `find` per root, and refuse or name the incomplete root.
- **WARNING, IN-SH-CODE-006 -- `scan` reads `devbin_version` and `source_commit` with its own awk**, and `recorded_commit` and `recorded_source` are two more copies, while `manifest_field` in `lib/helpers` exists, calls a second manifest reader a Highlander breach, and already behaves differently (it stops at the first non-comment line). Use `manifest_field`.
