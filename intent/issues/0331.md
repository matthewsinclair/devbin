A tool with a second binary that prints its own name fails doctor's dev and brew rows, so a tool like that cannot declare its link set

The dev/opt/brew contract (docs/dev-opt-brew.md, T4) has every binary of a tool print the tool's version line, and in opt and brew the line its manifest records. A 0.1.21 keg's manifest records one line naming the tool (lib/cmd/formula:501). Doctor's dev row runs each install.links path's --version against the line a build carries (lib/cmd/doctor:1134, failing at :1160), and its brew row fails each link whose copy prints another line (lib/cmd/doctor:1379).

A consumer whose second binary names itself, its daemon printing "<daemon> <version> (dev, <sha>)" while the tool prints "<tool> <version> (dev, <sha>)", fails both rows as soon as it declares both binaries under install.links: the dev row whenever the pair is built, and the brew row on every machine that installs its next release. A fresh clone with nothing built reads green, while a working checkout reads red. devbin-cc ran this on 2026-11-11 in a scratch clone of a consumer at its v0.1.21 sweep: doctor exit 1, "FAIL <tool> dev: native/rust/target/release/<daemon> prints <daemon> 3.2.8 (dev, ...), which names another tool or tree than the line a build here carries".

Until this is settled, such a consumer keeps the second binary outside the link set, as two template lines after @@INSTALL@@ (chmod 0755 and bin.install_symlink), with no install: block. That renders the same keg and reads green, but the contract no longer names the second binary.

Expected: one of two shapes, chosen by hv. Either the contract lets each link print the tool's line with its own name in place of the tool's (doctor reading each link's line under its link name), or it keeps one line per tool and says that every binary prints it, naming the consumer-side change that implies.

## Ruling

hv, 2026-11-11: the first shape. Each binary of a tool prints its own name in the first field of its line, with the tool's version, tree and sha from the core's one reader (the manifest's line in opt and brew, DEVBIN_VERSION_LINE in dev), and doctor's dev row and brew-tree row read each link's line under that link's name. Every binary of every tool reports its version the same way, so no binary keeps a formatter of its own. It ships in devbin 0.1.22, with 0329 and 0330.
