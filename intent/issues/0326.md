docs/dev-opt-brew.md (T1 to T10) is a contract that every tool released through Homebrew implements in its own code. The core every project vendors carries the release half of a tool's life (0323 retired three projects' copies of the ship steps), but nothing for publishing, identifying and switching a project's own binary. So the contract is only as uniform as each tool's hand copy of it, and the copies have drifted.

A review on 2026-11-06 (vc, at hv's word), against devbin's own switch (lib/cmd/use with lib/install), found:

- pplr#0001: Pplr carries its own Rust copy of install, the manifest, the tree, the version line and `use` (src/install.rs). It differs from devbin's: its opt prefix comes from an environment variable rather than a config key, `use dev` links a release build found through a path compiled into the binary, and its refusals differ.
- cldr#0001: Cldr has no publish, no switch and no tree identity, and its version line is `cldr <version>` alone. Its formula lays out libexec itself and ends with @@FINISH@@.
- ccusage#0007: Ccusage's `use` selects an account, so it has no switch. It has no publish or tree identity, its version line is the version alone, and its Linux formula runs cargo install, so a Linux brew install has no libexec tree and no manifest.

The contract names four tools (Molt, Utilz, Intent and devbin), each of which implements it in its own code, as the contract provides, and nothing checks a project against it.

hv's rulings (2026-11-06, in vc's window):

- devbin's approach is the canonical one for a Homebrew'd Rust or macOS CLI, and every project uses it, with every difference removed.
- The core carries it, filed as this issue for the next release.
- A new CLI under way in another estate waits for this and uses it, writing no switch of its own.
- In Ccusage, `use` becomes the dev/opt/brew switch, and account selection becomes `activate`.

Scope, design first. For a project that declares its binaries, the core provides:

- `install` (T2), publishing the dev tree to the opt prefix named by a config key, with T3's manifest;
- tree identity (T4) and the version line `<tool> <version> (<tree>, <sha12>[+dirty])`, with a compiled tool's sha and +dirty stamped into the binary at build, never read from HEAD at run time;
- `use [dev|opt|brew]` (T5) over the project's declared link set in ~/.local/bin, with the shadow check, and doctor's report of both;
- the formula's install (T8) in one form, for source and asset formulae alike.

A project then declares only its link set and its opt prefix in config.

Notes from the review: devbin 0.1.20's formula accepts @@FINISH@@ for a template that lays out its own assets (lib/cmd/formula:448-451), and T2 counts a formula that lays out signed release assets and writes T3's manifest as conforming. So Cldr's formula is valid today, and changes only under hv's ruling that every difference is removed.

Acceptance: Pplr, Cldr and Ccusage each run install, `use`, the version line and doctor's shadow check from the core, with their own copies removed, and pplr#0001, cldr#0001 and ccusage#0007 close against this; T10's proof passes for each; and docs/dev-opt-brew.md names the core's implementation as the one every tool uses.
