## What is wrong

Three comments in the shipped code name another of the owner's tools. Directive 14 on hv's board says that hv's own projects are never named in shipped code (bin/devbin and lib/), and every vendored tree carries these comments:

- lib/cmd/release:2543: `# A CUT FOUND ITS FORMULA COULD NOT RENDER ONLY ONCE IT WAS PUBLIC: Molt's 1.4.7`
- lib/cmd/formula:426: `# on a newer one. Molt 1.4.8's install failed there. So render writes the`
- lib/tool:167: `# out of no install that way, and a runtime set such as Utilz's (every tracked`

All three came in at devbin 0.1.30. hv accepts them for now, by this exact text, as for the machine name that Icbbfa7c removed.

## Fix

Keep each rule and its reason, and remove the tool's name, as Icbbfa7c did for the machine name.

A grep of lib/ and bin/devbin, case-insensitive and by whole word, for the name of each of the owner's projects finds these three lines and no others. Intent's name is in the code by design: the check critic and docs agents built-ins call the intent tool. That is outside this issue.

## Done when

- A grep of lib/ and bin/devbin for the owner's tool names finds none, Intent's name in the two built-ins aside.
