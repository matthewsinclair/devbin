Reported by Intent's dc on 2026-11-11, from Intent's 3.3.0 cut.

A release leg sends only the release commit to the leg host: `lib/release.legs:402` runs `git send-pack "$host:work/$project-leg.git" "$sha:refs/devbin/legs/$sha"`. The previous release tag never reaches the host's bare repo. On Intent's 3.3.0 cut, kovacs's `~/work/intent-leg.git` had no `v3.2.8`, so anything in the leg that reads the previous tag (eg a DEVBIN_RELEASE_* comparison, or notes since the last tag) had nothing to read, and the leg went red. v3.2.8 was sent into the leg repo by hand before the run that passed.

Ask: the leg's send-pack carries the previous release tag, the baseline the release core resolves, alongside the release commit, so a fresh leg repo needs no hand step. Intent's cut passed with the hand send; nothing to build for Intent.

## Resolution

Fixed in one landing on main, 720fa0b2e39b579b3e426261b28df5ce0a93324a (2026-11-12 05:41Z), unit 0333-1 from the tested tip 9fdb4533, first in devbin 0.1.23's batch; released in devbin 0.1.23, proved on its own arms under hv's rule of 2026-11-05 (red at the base's code, green at the fix) in one slot on devbin-vc's desk with 0334-1.

- A remote leg's start is sent the previous release's tag beside R, by the same send-pack, forced over an older copy the host's bare repo holds, so a gate that reads the last release finds it in a fresh leg repository. A tag this repository does not hold is the start's unknown, naming it, and nothing is sent.
- release_previous_tag (lib/release.steps) names it: the newest release's tag other than the target's own, by version, not by spelling, and nothing when no other tag names a release.
- The cut reads it only for a cut with a remote leg, so a cut without one reads no tag for it.
- docs/configuration.md's legs step and the release page's "The gates' own directories" say so (written with 0335-2).

Two new arms in releaselegs.bats, both red at the base on their own finding (the host's bare repo held no tag, since the base sends R alone; release_previous_tag was no command) and green at the fix. Intent's hand send of its previous tag into a fresh leg repo is no longer needed.
