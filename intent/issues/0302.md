Issue 0300 was this class, found on kovacs (Ubuntu, a hostname without a domain), where git refused the identity it guessed ("unable to auto-detect email address (got 'matts@kovacs.(none)')") and a releasestatus.bats arm went red that was green on every Mac: there git guesses an identity from what the host's name and resolver give (on rhadamanth, under the harness's settings, a Tailscale MagicDNS address), and the commit goes through under it.

tests/lib/test_helper.bash empties the global and system config (GIT_CONFIG_GLOBAL=/dev/null and GIT_CONFIG_NOSYSTEM=1, :77-78) and leaves git free to guess, so any later arm or fixture whose repository has no identity is host-shaped the same way until a host like kovacs runs it. Its comment at :76, "No identity is lost: every fixture that commits passes its own", misses devbin's own commits, which pass none (0300).

Fix (cc, after ST0011 WP02a): GIT_CONFIG_GLOBAL points at a file the harness writes, holding only `[user] useConfigOnly = true`, in place of /dev/null, with harness.bats's pin of it (:105) changed to match, so a commit with no identity configured exits 128 ("no email was given and auto-detection is disabled") on every host and an arm that leans on a guess goes red where it is written. Measured in scratch by the 0300 review: with that file the commit exits 128, and a commit with an identity given exits 0. Not GIT_CONFIG_COUNT, which `git rev-parse --local-env-vars` lists and devbin's git_local_env_clear unsets; GIT_CONFIG_GLOBAL is on no such list. Arms that set their own GIT_CONFIG_GLOBAL (releasecut.bats, releasesnapshot.bats, worktrees.bats) keep theirs. With it, the -c identity pairs that git_project's callers pass on commits and tags in its projects (macos.bats, releaseattach.bats, releasesnapshot.bats, releasestatus.bats: sixteen, as the 0300 review counted them) are redundant and go, and :76's comment says where a fixture project's identity comes from. Its run is the whole suite, since the harness change reaches every arm.
