## What is wrong

In source mode, `bin/devbin formula` refuses `formula.cask`. `lib/cmd/formula` (formula_settings, the source arm) says: "formula.cask is declared, and formula.mode is source, which reads it nowhere". A project whose formula builds from source cannot also ship a cask for an app it releases as a zip. Gtools asks for this (Gtools I17c1577).

## What to change

- In source mode, take `formula.cask` as assets mode takes it. `formula.repo` and `formula.assets` stay refused in source mode.
- The cask template holds `@@VERSION@@` and one `@@SHA256:<name>@@` for each file it downloads. render reads each sum from the release's sums file (`formula.sums`, default `SHA256SUMS`, or `--sums <file>`), as assets mode does. In source mode the cask's assets are the names its `@@SHA256:...@@` placeholders hold.
- `render <tag> <out> <cask-out>` writes both files. `publish` writes the cask to `Casks/` beside `Formula/<name>.rb`. `check` checks the cask with a stand-in version and sums.
- The formula's own source install does not change.

## Arms

- A source-mode project with `formula.cask` renders the formula and the cask, and the cask holds the version and the sum from the sums file. Red at main, which refuses the cask.
- In source mode, `formula.repo` and `formula.assets` are still refused.

Size S. P3, behind devvm. Gtools' cask also waits for hv's decisions on notary credentials and a public home for the zip.

Resolution: Fixed in v0.1.32 (landed at 55f48494). In source mode, formula takes formula.cask: render writes the cask from the release's version and sums, publish pushes it to Casks/ in the same commit, and check checks it. formula.repo and formula.assets stay refused in source mode. A cask takes @@VERSION@@, @@SHA256:<name>@@ and @@REVISION@@, and no @@TAG@@. Proof: Desk run 01M87FZ8XYZCRRW99PGK9YCC0Q, 2 arms red at main and green at the tip under BSD and GNU.
