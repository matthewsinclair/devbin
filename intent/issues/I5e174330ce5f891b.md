## What is wrong

A source-mode formula's install fails on macOS unless its template happens to depend on bash. The rendered body runs the core's publish, `system "bin/devbin", "install", "--prefix", libexec, "--managed-by", "brew"` (`publish_ruby`, `lib/cmd/formula`; `install_ruby` writes it as source mode's whole body). `bin/devbin` refuses any bash below 5 (`lib/helpers:119`). Homebrew's build on macOS has `/bin/bash` 3.2.57 unless the formula depends on a newer one. And the renderer asks for none: it checks a bash dependency only where `formula.bash` is true, whose env scripts need it (`lib/cmd/formula:711`).

Molt 1.4.8's `brew upgrade molt` on macOS failed there, inside `@@INSTALL@@`'s body: "devbin: bash >= 5 is required; this is bash 3.2.57(1)-release (/bin/bash)". devbin's own formula works only because its template depends on bash for its own reasons (`packaging/homebrew/devbin.rb:30-31`).

Who is exposed, by template as each stands on its main:

- **Molt**: was broken, and now carries a stopgap of its own, `on_macos do depends_on "bash" => :build end` (Molt 526e5bc), which gives molt 1.4.8 (brew, 326d469d4709) on rhadamanth.
- **Gtools**: carries the same line already (`gtools.rb:36-37`), so it is safe by its template's own choice.
- **Utilz**: its template has no bash dependency (`utilz.rb:18-26`). It would break the moment its adoption (Utilz I59c806c) moves its install to `@@INSTALL@@`, and its plan carries the same stopgap.
- **Pplr, Cldr and Intent**: assets mode. Their bodies run `bin/devbin` only when the stage holds one, and their release assets hold only the tool's own files, so the assets branch runs and needs no bash. An assets formula that builds one platform from the tag's checkout would meet the same failure on that platform.

So the rule each template must remember is unwritten anywhere it would be checked, and the first template to forget it breaks every user's install.

## Fix outline

Wherever the rendered body can run `bin/devbin`, the formula depends on a bash that meets devbin's floor at build time, and a template no longer carries that line itself:

- render writes the dependency itself: `on_macos do depends_on "bash" => :build end`, or the form that also covers Linux if the plan finds Linux brew's build bash can be older than 5. It goes at the class level, for source mode and for an assets formula whose body can take the publish branch.
- Where formula.bash is true the template's own runtime `depends_on "bash"` stays its own, since that is a runtime dependency, and render's build line beside it is harmless. The plan decides whether render folds the two.
- `formula check` (devbin I3ce05fa) and render both refuse a template that writes its own bash build dependency, naming it, so the line has one home, as `post_install_steps` does since I514ea74.
- `docs/dev-opt-brew.md`'s T8 and the formula page say the body's bash is render's.
- Molt's 526e5bc and Gtools' own line then go, each in its estate's sweep to the release that carries this. Utilz's plan drops its own.

## Done when

- A source-mode render of a template with no bash line holds `depends_on "bash" => :build` under `on_macos`, and a `brew style` of it passes.
- render and check refuse a template that writes its own bash build dependency, in render's words.
- It ships in devbin 0.1.30 beside I3ce05fa and I2bae9ce, ahead of Utilz's and Gtools' adoptions.
