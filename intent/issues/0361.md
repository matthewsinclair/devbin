Two release-gate defects, built as one unit (decision 194).

1. A red remote leg's log says nothing about what the leg left in its TMPDIR. The leg's log should carry the TMPDIR's top-level files when the leg goes red (lib/release.legs:245). Only the top level is listed; the limit is accepted.

2. The gate cache grows without bound. It measured 15.2 GiB on rhadamanth and 8.1 GiB on kovacs (2026-11-16). Each run should bound the cache when it starts: a 12 GiB constant that a release config can override.

Scoped by dc (vc's inbox, committed at ac7501c1 and 422c1bf0); hv chose the bound and the override on 2026-11-16 (decision 194).

## Resolution

Fixed by unit 0361-1, landed at 31f2ddf4, for 0.1.26 (written 2026-11-16 16:58Z by date -u).

1. A remote leg whose gates end with a status other than 0 now appends each regular file at the top of its TMPDIR to the leg's log, before the status is written and before the run is cleared. Each file goes under a line naming it, and the log's last line is written again after them, since a run that ended with no pair is named by that line. The run's own detached command does it (lib/release.legs, _release_leg_remote_start), so it adds no ssh call and leaves read, finish and clear unchanged. A directory in the TMPDIR is not read, and a green run appends nothing. Below the top level, what a gate writes still goes with the clear, the limit hv accepted.

2. gate_cache_bound (lib/release.legs) is the one rule for a gate cache's size: a cache over its bound is emptied before the gates start, made writable first, so that run builds cold, and one within it is kept. Each leg's host applies it at the start, and the leg's log says what was done (kept with its size, emptied with the size it held, or left as it stands while another run of the project is going on the host). This machine's .gate-cache is held to it in gates_cache_dir (lib/cmd/release), which says on stderr when it empties one. release_leg_remote sends the rule beside each remote half, so it is stated once. The bound is release.gate_cache.max, a whole number of M or G above 0, 12G by default, read by the cut and release gates. The cut and release gates --leg pass it to each host in KiB, since lib/release.legs reads no config. lib/pages/release.md, docs/configuration.md and lib/config.reference.yaml document it.
