dc ran `bin/devbin release gates` (check all, test all, doctor) on a Desk slot in a fresh clone at 3c804a37 on 2026-11-13, 11:25:57Z to 11:43:16Z by date -u, and it was green. TMPDIR was shaped as a leg's, an empty directory beside the tree. After the run, the top of that TMPDIR held 18 entries: update-notice stamps, `devbin-git.*` files and `node-compile-cache`. The record is ~/Devel/scratch/devbin-dc/g24/run-g24.out ("TMPDIR after: 18 entries") and the seal pair in g24/seals/3c804a37. The names beyond those three kinds were not kept, and that TMPDIR is gone.

## The code

- The update notice keeps its stamp in TMPDIR by design (devbin_update_notice, lib/helpers:6906-6931: "The stamp lives in TMPDIR rather than the project, so it needs no .gitignore entry"). It writes one only when stderr is a terminal (:6910), and each project root has a stamp of its own name (:6914), so the stamps come from arms that run bin/devbin with stderr on a terminal.
- release_git_remote takes git's stderr into `mktemp "${TMPDIR:-/tmp}/devbin-git.XXXXXX"` and removes it after the call, but "A call killed at its bound (release_run_bounded) prints none of what it said and leaves its file under TMPDIR" (lib/release.steps:847-851). Each arm that kills a remote call at its bound leaves one.
- `node-compile-cache` is Node's own module cache, under the TMPDIR of a Node tool that ran. bin/.devbin/config.yaml names no Node tool.

On a leg host the gates' TMPDIR is the run's own, <worktree>.tmp, and goes with the worktree (lib/release.legs:222-228). A cut's local leg runs in place with this machine's TMPDIR, so what a run leaves there stays until the OS clears it.

## Options, none chosen
