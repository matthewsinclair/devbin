tests/unit/infra-check.bats's arm 'a missing resolver is ONE error naming the tool, not one row per domain' builds a PATH without dig: it links every name in /usr/bin and /bin into one directory and runs infra check with that directory alone on PATH. It skipped a name already linked by testing `[ -e "$NODIG/$b" ]`, which follows the link. On a merged-usr system /bin is /usr/bin, so every name comes round twice, and a dangling link in /usr/bin reads as absent on its second pass: `ln -s` runs again, refuses with "Already exists", and the arm fails before it reaches infra check.

GitHub's Ubuntu runner holds such a link, grub-ntldr-img, and the 0.1.19 candidate's CI failed on this arm alone: run 41342983331, job 124956747947 (Test on Ubuntu), not ok 1215 at d14e9b3c, its failure line `ln: failed to create symbolic link '/tmp/devbin-test.HH2DZE/nodig/grub-ntldr-img': Already exists`. Neither rhadamanth nor kovacs has a dangling link in /usr/bin, so the arm is green there by construction, and neither the cut's local gates nor K0120 could show it.

Fix: test for a name already linked with `[ -L ]`, which is true for any link, dangling or not; every entry in the farm is a link. A plain-bash copy of the loop, run under errexit over a merged-usr layout whose usr/bin holds a dangling link, fails with `-e` exactly as CI did and passes with `-L` (~/Devel/scratch/devbin-dc/fix-nodig-probe.sh). The suite's other link farms are safe: test_helper's path_without links each PATH entry into a fresh directory of its own, and fullcycle's fixture_links only counts links.

Medium: no user-facing defect, but it turns a cut's Ubuntu CI red wherever the runner's /usr/bin holds a dangling link, and it stopped the 0.1.19 cut. In 0.1.19, on the release's path (vc's ruling under decision 129).
