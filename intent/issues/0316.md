gate_spans (tests/lib/test_helper.bash), the one reader the gate scans share (dispatch.bats 0087's split-argv arm and runlog.bats 0085's --source arm), starts a span on any non-comment line holding `run_gate ` followed by a space, as a substring with no word boundary. So a name that merely ends in run_gate reads as a gate call: WP02c's local `unrun_gate` did, at three lines of lib/cmd/release's pre-flight, and both scans reported "a run_gate with no bare --" there until the variable was renamed unrun_entry. Earlier the same day the hook-in's `declare -F run_gate` dependency check in lib/release.macos read as a call too (fixed by dropping the check, which seal_verdict already covers).

A name is the wrong fix each time it happens. The reader should match run_gate as a word: preceded by start of line, whitespace or a shell operator, and followed by a space, so `unrun_gate x` and `declare -F run_gate` are not spans while every real call still is. The arms' own non-vacuous checks (0087 counts the split sites a second way, 0085 refuses an empty span list) keep a narrowed reader honest.

Low: no wrong answer reaches a user; the cost is a false red in the whole suite, met only there. For after the release (vc, 2026-11-01).
