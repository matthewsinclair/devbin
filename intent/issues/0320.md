On 2026-11-02 this repository moved onto GitHub's history with the workroom public (vc decision 132): main is the public main, local and upstream are ordinary remotes, and nothing is snapshotted any more. devbin's own release config still declares the snapshot shape (release.publish.url and release.snapshot, release.remotes local alone), so the next cut refuses at pre-flight, since the upstream remote names the repository release.publish.url names (publish_url_named), and a snapshot cut would put a commit on GitHub's main that this checkout's main lacks, so the next ordinary push to upstream would be refused.

## Fix

- `bin/.devbin/config.yaml`: drop `release.publish` and `release.snapshot`, and declare `release.remotes` as local then upstream. The cut then takes the core's standard shape, as every other project's does: the legs step pushes the release commit itself to `candidate/<tag>` on upstream, the remote that pushes to `release.repo`, reads CI green there beside the local gates and the kovacs leg, then tags and pushes the release commit and the tag to both remotes. Its comments say so.
- `docs/releasing.md`: the procedure, step list and Homebrew section in the standard shape.
- `packaging/homebrew/devbin.rb`: the comment over its url names the release commit, not a snapshot. The formula's behaviour does not change: with no publish.url, render reads the tag's commit in this checkout, the release commit GitHub holds.
- `tests/unit/ci-state.bats`: the arm pinning devbin's snapshot shape pins the standard shape instead (no publish.url, remotes local then upstream, the built-in query).

The core's snapshot feature stays for any project that declares release.publish.url.

## Done when

1. devbin's config declares neither key, and its remotes are local then upstream; `bin/devbin release check` reads the standard shape and says a push of the candidate's branch starts tests.yml.
2. A dry run of the next cut passes the remotes and candidate pre-flight (refusals that wait on the next release's note are expected).
3. The changed arms and the files that read these paths pass under BSD and GNU, with the tree scans and help; CI is green on the pushed head.
