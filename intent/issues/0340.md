## What happens

lib/bats-lanes runs the parallel lane as `bats --jobs N --filter-tags '!serial' <dir>` (lib/bats-lanes:210). N defaults to half the CPUs and never fewer than two: 2 on kovacs, which has had 4 vCPUs since hv resized it on 2026-11-12, and 8 on rhadamanth.

`bats --jobs N` runs N files at once through GNU parallel. It also runs the tests inside each file through `bats-exec-file -j N`, and every file of the run shares one semaphore of N slots, kept in the run's own temp directory (bats-core's lib/bats-core/semaphore.bash). When a file's next test finds no free slot, the file sleeps a whole second before it looks again (`sleep 1`, under "TODO: avoid busy waiting"). bats 1.12.0, kovacs's, and 1.14.0, rhadamanth's, have the same code. macOS has no flock, so there the lock around taking a slot is shlock, and that polls with `sleep 1` too. A freed slot stays idle until a sleeping file wakes, so a suite of short tests spends most of its wall time asleep.

## Evidence

- devbin 0.1.23's third cut, 2026-11-12: kovacs's leg had run 1230 tests in about 30 minutes when kovacs-sysadm stopped it at hv's word (09:28:29Z, vc's relay). rhadamanth runs all 3121 in about 10.
- hv: "The SLEEPS take more time (by a factor of 4 or 5) than the actual tests!"
- kovacs-sysadm sampled the sleeps. All of them came from `bats-exec-file -j 2` (fullcycle.bats, harness.bats) under `parallel --jobs 2`. The VM was 53 to 83% idle, with no iowait and no swap.
- The suite has sleeps of its own as well (fullcycle.bats's `sleep 3`, the `sleep 10` watchdogs, the polls in heartbeat, contract, surfaces and releasecut). Those are the tests' own waits, not the runner's.

## The fix

Cut the suite's wall time where the waiting is, on every host, without losing coverage or isolation. Measure before choosing, on rhadamanth and on kovacs, over representative files that include releasecut, fullcycle and harness. Compare:

- the current split;
- `--no-parallelize-within-files`, which runs each file's tests one at a time and whole files N at a time under GNU parallel, with no semaphore;
- N itself. Half the CPUs is low for a suite that mostly waits, and a large file run alone can become the long pole.

lib/bats-lanes ships to every estate through the sweep, so the fix says what it changes in their suites.

## Proof

- The lanes' arms in tests/unit/testhandler.bats go red at dc0e45b8 and green at the fix, BSD then GNU.
- One stacked run proves the fix together with cc's fixes for the 0.1.23 cut's two reds, before the re-cut.
- A timing fix has no time to assert. Its red is the pinned shape of the parallel lane's bats command, and the timings stand as the measurement's own record.
