From Intent's ST0093 (hv's word, relayed by intent-vc, 2026-11-11), half B item 4.

Intent's 3.3.0 cut built its release pair 8 times, of which 3 shipped. Locally it was built 3 times from the same sources. Every build except the first rebuilt inputs whose git objects had not changed.

Where the builds are, all of them Intent's own commands:
- `stamp cli`, a derived step, before R exists (Intent's config.yaml:406-408).
- `gate pair` and `build all` in release.gates (config.yaml:418-449, 537-540).
- The leg tree's pair for `test shell` (Intent 73c6ec84a).
- `cut publish`, after the tag (config.yaml:451-459).
- CI's macOS and Ubuntu jobs.

The core already has the mechanism. `cache key/get/put` (ST0011 WP-16, lib/cmd/cache) is keyed on the git objects of the declared inputs at a commit. A build whose inputs did not change pulls instead of building. No consumer calls it outside the macOS stage (lib/cmd/macos:1393-1414).

What the core lacks:
1. A way for a project's own build handler to pull or put through the core's cache without going through its launcher. That is item 3's fix 1, and it is a prerequisite here.
2. A rule for a stamped build. A put needs a clean input tree, so `stamp cli`, which builds before the stamp is committed, has no key and records nothing. The first build that can be cached is the one at R. `cut publish` at the tag reads the same tree as R (the tag points at R), so it pulls.
3. The cut's RELEASE seal names each cached artefact's key at R, as `legs_cache_lines` (lib/cmd/release:1412-1441) already does for the macOS app. Extended to every artefact in build.artefacts, `cache gc` keeps every one a release names.

Ask: 1 is item 3's first fix. For 3, `legs_cache_lines` covers every declared build artefact, not only macos.app's. The page for `cache` (lib/pages/cache.md) shows a build handler calling get and then put. Most of the saving is Intent's adoption: a build: block declaring the pair and handlers that call get and put. That is Intent's package.

Proof: Intent's next cut, whose log shows one build of the pair at R and a pull everywhere after.

Size S in the core, after item 3. Intent's adoption is M on its side.
