Found by the critic-shell review of ST0011 WP02a (2026-10-31), outside that unit. lib/cmd/worktrees clears git's repository-local variables (GIT_DIR, GIT_INDEX_FILE and the rest that `git rev-parse --local-env-vars` lists) through git_local_env_clear at file scope (lib/cmd/worktrees:158 at main) before remove-landed's writes, `git -C <path> reset --hard` and `git worktree remove`, and names none it drops: an inherited GIT_DIR, from a hook or another worktree, is cleared in silence, so the person never learns the run ignored the repository their environment named.

ST0011 WP02a adds git_local_env_clear_named <who> <root> (lib/helpers, on refs/bank/cc/ST0011-02a), the one clear that names what it cleared, with the repository used instead, on one line; the cut, release status, release gates and lib/cmd/macos's read of the release commit call it.

Fix (cc, after ST0011 WP02b, since the helper lands with WP02a): worktrees clears through git_local_env_clear_named, so it names what it drops as the cut's clear does, and stops on either of its failures, saying which; an arm runs remove-landed under an inherited GIT_DIR and reads the line.
