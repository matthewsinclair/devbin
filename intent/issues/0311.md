Found by the issue 0297 fork's review of ST0011 WP02b-2 (2026-11-01), off that unit's path, and held for after the release on vc's word. lib/cmd/macos:717, in drop_check_copy, restores only the traps `trap -p` printed. A caller that saved INT alone would be left with TERM and HUP ignored. No caller does that today: lib/cmd/macos's one trap set, at line 591, covers INT, TERM and HUP together, so the three are always saved and restored as one. Fix, after the release: reset each of the three to its default before the saved handlers are evaluated, as run_gate's restore does (0297).

## Resolution

Fixed at ac657c2cd4de9ed061fafe29f356090810f24357, landed on main by devbin-vc's land-stack.sh as one unit of group B's four (0298, 0299, 0311, 0305), unpushed until the 0.1.20 cut. lib/helpers gains traps_restore <saved> <signal>..., which resets each named signal the saved trap -p text does not name to the default before evaluating the saved handlers. drop_check_copy restores through it, and so does run_gate in lib/runlog, whose loop it was, so the tree keeps one copy. A reset that fails returns non-zero. helpers.bats saves TERM alone, ignores TERM, HUP and USR1, restores them, and reads HUP and USR1 back at the default. It was proved in group B's run on pplr-vc's desk, with each driver's kit read by devbin-vc first.
