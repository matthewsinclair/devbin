## What happens

bats runs the parallel lane's files under GNU parallel with `--keep-order`, so each file's results are held until every earlier file has printed. A slow early file holds the whole log back.

On CI's three-CPU macOS runner, for devbin 0.1.23's candidate:
- the log sat 1761 s before contract.bats's first result, while about 2700 later results waited;
- on the next candidate it was parked at `ok 392` for over half an hour.

Both runs were working. Read live, each looked wedged.

run_gate's heartbeat exists for exactly this question, "is it hung?", but it has two limits here:
- it beats only when a terminal is attached, so CI's log never shows it;
- it can say only how long the run has been quiet, since it knows nothing of what the command has done.

## Where

- lib/runlog: `gate_heartbeat_start` and `run_gate`.
- lib/bats-lanes: its recorder (issue 0345) knows each file's start and end as they happen, whatever order bats prints in.

## Fix

run_gate gives its command a file to write progress to, DEVBIN_GATE_PROGRESS, as it gives it DEVBIN_GATE_LOG.

- The heartbeat reads that file on each beat and adds its line, eg `the parallel lane: 37 of 69 files done (1210 of 3127 tests), 24 running`.
- With no terminal attached it beats only when the command has written progress. So every gate that writes none keeps its redirected output unchanged to the byte, and CI's log shows the lanes' progress whenever the log has been quiet for a beat.
- The heartbeat still writes only to run_gate's own stderr and never to the captured log, so the TAP that the seal and the count read is unchanged.

bats-lanes writes the line from its recorder as each file starts and ends:
- the files and tests done, read from bats's own test list;
- how many files are running.

It writes the serial lane's line when that lane starts. It takes DEVBIN_GATE_PROGRESS out of the environment it hands bats, so a run that a test starts cannot write to the outer run's progress.

## Acceptance

- Under a gate with no terminal, a lanes run whose output is held prints beats on run_gate's stderr naming files and tests done.
- The captured log holds none of them.
- A gate that writes no progress prints no beat without a terminal, as before (heartbeat.bats's no-terminal arm stays green unchanged).
- A lanes run that a test starts inside the lane leaves the outer run's progress file untouched.

## Resolution

Fixed in one landing on main, 58344954 (unit 0346-1), on 0345-1 (03942c76), after devbin 0.1.23, so it ships in the release after it.

- run_gate gives its command a file to write progress to, `DEVBIN_GATE_PROGRESS`, as it gives it `DEVBIN_GATE_LOG`. It removes the file when the run ends.
- The heartbeat reads that file on each quiet beat and adds its first line, eg `the parallel lane: 37 of 69 files done (1210 of 3127 tests), 24 running`.
- With no terminal attached, it beats only when the command has written progress. So a gate that writes none keeps its redirected output unchanged, and CI's log shows the lanes' progress whenever it has been quiet for a beat.
- The heartbeat still writes only to run_gate's own stderr, never to the captured log, so the TAP that the seal and the count read is unchanged.
- lib/bats-lanes writes its line from 0345-1's recorder as each file starts and ends: the files and tests done, counted from bats's own test list, and how many files are running. It writes the serial lane's line when that lane starts, and empties the file once its lanes have ended.
- bats-lanes takes `DEVBIN_GATE_PROGRESS` out of the environment it hands bats, so a run a test starts cannot write to the outer run's progress.
- bin/.devbin/help/test.md and lib/pages/test.md say the run reports its progress on stderr while its output is held.

Proof, in the same slot as 0345-1 (01M78JPC65EJT23EKR5VMP3WKJ, rhadamanth alone, 2026-11-12 19:11Z to 19:27Z, at 02f08381):
- heartbeat.bats gains two arms:
  - with no terminal, a command that writes progress gets beats carrying its line, none of it enters the log, and the file goes with the run;
  - a lanes run's beats count the files and tests its parallel lane has finished, out of the suite's.
- testhandler.bats gains one: a lanes run takes the gate's progress file out of what it starts, and leaves it empty once its lanes have ended.
- At 0345-1 without this unit's code, each of the three failed on its own finding:
  - no "still running" beat;
  - no beat carrying the lane's progress;
  - the fixture's test saw `DEVBIN_GATE_PROGRESS`.
- At the tip, heartbeat.bats was green 11 of 11 under BSD and under GNU tools with mawk as awk. Its existing no-terminal arm, unchanged, holds that a gate writing no progress prints no beat. testhandler.bats was green 23 of 23 under both.
