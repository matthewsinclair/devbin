## What happens

bats runs the parallel lane's files under GNU parallel with `--keep-order`, so each file's results are held until every earlier file has printed. A slow early file holds the whole log back.

On CI's three-CPU macOS runner, for devbin 0.1.23's candidate:
- the log sat 1761 s before contract.bats's first result, while about 2700 later results waited;
- on the next candidate it was parked at `ok 392` for over half an hour.

Both runs were working. Read live, each looked wedged.

run_gate's heartbeat exists for exactly this question, "is it hung?", but it has two limits here:
- it beats only when a terminal is attached, so CI's log never shows it;
- it can say only how long the run has been quiet, since it knows nothing of what the command has done.

## Where

- lib/runlog: `gate_heartbeat_start` and `run_gate`.
- lib/bats-lanes: its recorder (issue 0345) knows each file's start and end as they happen, whatever order bats prints in.

## Fix

run_gate gives its command a file to write progress to, DEVBIN_GATE_PROGRESS, as it gives it DEVBIN_GATE_LOG.

- The heartbeat reads that file on each beat and adds its line, eg `the parallel lane: 37 of 69 files done (1210 of 3127 tests), 24 running`.
- With no terminal attached it beats only when the command has written progress. So every gate that writes none keeps its redirected output unchanged to the byte, and CI's log shows the lanes' progress whenever the log has been quiet for a beat.
- The heartbeat still writes only to run_gate's own stderr and never to the captured log, so the TAP that the seal and the count read is unchanged.

bats-lanes writes the line from its recorder as each file starts and ends:
- the files and tests done, read from bats's own test list;
- how many files are running.

It writes the serial lane's line when that lane starts. It takes DEVBIN_GATE_PROGRESS out of the environment it hands bats, so a run that a test starts cannot write to the outer run's progress.

## Acceptance

- Under a gate with no terminal, a lanes run whose output is held prints beats on run_gate's stderr naming files and tests done.
- The captured log holds none of them.
- A gate that writes no progress prints no beat without a terminal, as before (heartbeat.bats's no-terminal arm stays green unchanged).
- A lanes run that a test starts inside the lane leaves the outer run's progress file untouched.
