## What is wrong

devbin 0.1.31 (issue I6b3b75f) refuses an opt publish when the checkout has no `.devbin-tool`. The refusal is correct and stays. But 0.1.31's note does not say that a project's test that builds a copy of the checkout and publishes from it must now copy `.devbin-tool` too. Utilz main went red after the 0.1.31 sweep: 9 tests failed with "refusing to publish utilz: this checkout's .devbin-tool is missing". The sweep's report said only that it wrote the file.

## What to change

1. When `bin/devbin upgrade` (the sweep) writes `.devbin-tool` where there was none, its report says that a test that builds a copy of the checkout to publish from must copy `.devbin-tool` with the tree, or the publish refuses it.
2. The next release note's "Changed" section says the same, and names what to copy: `.devbin-tool` at the project's root, beside `bin/.devbin/config.yaml`.

Do not change the refusal.

## Arm

An upgrade in a tool project that has no `.devbin-tool` writes the file and prints the line about a copied checkout. Red at main, which prints only the `wrote` line.

Resolution: Fixed in v0.1.32 (landed at 85f1d90c). When upgrade or build writes .devbin-tool where there was none, it prints a note: a test that builds a copy of the checkout to publish from must copy .devbin-tool. The fleet sweep's report names each note in a Notes table, and a note does not hold the estate. The refusal does not change. Proof: Desk run 01M87FKDT7S9HZFDHCR0XAE1Y9, 2 arms red at main and green at the tip under BSD and GNU.
