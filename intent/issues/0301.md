Found by the critic-shell review of issue 0300's fix (2026-10-31). tests/lib/release_fixtures.bash's git_project checks none of its steps and returns its last command's status (gh_stub_more's cat), and cut_project checks none of its own and returns printf's 0. Every builder that calls git_project outside releasecore.bats (cut_project; releasestatus.bats's released_project; macos.bats's app_project; releaseattach.bats's attach_project and from_project; releasesnapshot.bats's snap_project) is used as proj="$(builder)", where bash turns errexit off (bats-core 1.14.0 and test_helper.bash set no inherit_errexit), so a step that fails is never seen and the arm goes on with a project half made.

The measured case: releasestatus.bats's arm "object: none, an undeclared after: and an undeclared ci.query are skipped, and a declared one is not" (main, :329) builds a second released_project (:339) in the same directory, create_test_project always making $DEVBIN_TEST_TMPDIR/demo, and git_project's `git remote add origin` (release_fixtures.bash:98 at 0300's bank 1b29205a) exits 3 on every run ("error: remote origin already exists."). The arm is green only because origin already names the same URL.

The gh stub git_project writes is the same shape: its create and edit branch writes three files and exits 0 whether they were written or not, where gh_stub_more (release_fixtures.bash:218) has a stub that failed to do a thing exit non-zero, as gh would; its view branch's 2>/dev/null reads (:146, :148, :149) carry no comment saying a missing file means no release, or an empty name or body.

Fix (cc, after ST0011 WP02a, since releasestatus.bats and macos.bats are WP02a's files too): every step of git_project and cut_project returns its failure, as test_helper.bash:1622 asks of fixture steps and install_devbin does; each builder calls `git_project "$proj" || return 1`; the arm at :329 clears the first project and its remote before the second build, as the arm at :670 does (rm -rf of demo and remote.git), which the change turns red until it does; the stub's create and edit writes exit 1 when they fail, and its 2>/dev/null reads are commented. Its run: every git_project caller's file (releasecut, releasestatus, releasecore, releaseattach, releasesnapshot, macos) under BSD, releasestatus and releasecut under GNU, the tree scans and help.
