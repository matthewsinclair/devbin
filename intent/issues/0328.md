The release commit carries a declared trailer, so a project's release commit meets the house commit rule.

## The gap

The core commits the release commit with `--only` and `-m "release: $tag"` and no body (`lib/cmd/release:2809`). So every project cutting through the core gets a one-line release commit, devbin's own included: `be40dea7`, devbin 0.1.20's release commit, reads exactly `release: v0.1.20`.

The house rule is that a commit message ends with the maintainer's `(C)` line. A machine-made commit is still a commit in the history, so the core's release commit falls short of it in every project at once. Intent's driver works around it by adding the line itself as a second paragraph, which is a local patch of a core behaviour, and the kind of divergence that drifts.

## The ask

A declared trailer, appended to the release commit's message as a second paragraph. The subject stays `release: <tag>`, so the tag readers, `release status`, `release_commit` and the formula are untouched.

Devbin declares its own with the rest, so devbin's next release commit carries the line, and Intent drops its driver's addition.
