Filed for devbin 0.1.27's batch (vc's decision 205, which carries vc's todo 214), from vc's archived todo 208: kovacs-sysadm's reading of 2026-11-12.

## What happened

kovacs held ~/work/devbin-leg-9b674c0e0437, with its .log and .rc, from 0.1.21's first cut at 9b674c0e, which stopped red and was reset and re-cut. Nothing cites it, and nothing cleared it. Its removal is hv's word in kovacs-sysadm's window.

The kovacs leg did not fail there. That cut's log, tmp/release/20261110-1839.RELEASE.out, reads the local leg failed on `test all` while kovacs was still running, and then: "release: legs: legs.kovacs is left to finish on its host; its seal lands in tmp/release/legs/kovacs/ when read". The re-cut was at another commit, so nothing read 9b674c0e's run again.

## The code

A leg's run is cleared from its host only by a read. release_leg_read (lib/release.legs:573) calls _release_leg_finish (:469) once it reads the run as ended (:640, :674, :683 and :687). That copies the log back and then runs _release_leg_remote_clear (:371) on the host, which removes the worktree and its TMPDIR, <worktree>.tmp (:222-228). So a run is left on the host whenever no read finds it ended:

- A cut that stops red leaves each remote leg still running to finish (legs_stop, lib/cmd/release:1442-1448), and a re-cut is at another commit.
- A run still going at its leg's deadline is a timeout, and is left on the host "to be looked at there" (lib/release.legs:73-75).
- A log that cannot be copied back keeps the run there for the next read (:471-475).

A start at another commit does not clear these: its loop over the project's other worktrees (:272-279) looks only for one still going, to leave the gates' cache as it is.

## Options, none chosen

- At each start, clear every ended run of the project on the host, at any commit, after copying its log back as a read would; a run still going is left as it is now.
- A verb, or a doctor row, that names the ended runs a host holds and clears them on the maintainer's word.
