A declared tool that keeps its own switch and publish has devbin's use and install offered beside them, so two writers own its links and its opt tree

A tool that declares install: (its link set under install.links) becomes a devbin tool. Its checkout then offers `bin/devbin use` and `bin/devbin install`, which write ~/.local/bin/<name> and publish an opt tree. A tool that already ships its own switch and publish, eg a Rust tool with its own `use` and `install` subcommands, would have two writers of the same links and two publishers of the same opt tree. T5 says a tool gives up its own verb when it adopts the core's, and a tool that cannot do that yet has no way to declare its link set for the formula and doctor.

hv's ruling of 2026-11-11 (decision 157, by menu in a consumer's vc's window and confirmed in vc's TUI) is that devbin withholds its verbs for such a tool.

Expected: two keys under install:, install.switch and install.publish, each naming the tool's own command as typed. devbin shows these and never runs them. Under install.switch, `bin/devbin use` refuses, exit 1, writing nothing, and names the tool's command. Under install.publish, `bin/devbin install` with no --into refuses the same way. Vendoring with --into, and the formula's publish into a keg (--managed-by brew), are unchanged. The formula, the link set and doctor's rows read install.links as before, and doctor's remedies and the cut's closing note name the tool's own commands.

## Resolution

Fixed in one landing on main, 00b9445cf10229438d3ffb7fd76df5be0a6adacd (2026-11-11 07:11Z), unit 0332-1 from the tested tip 0c88c63d, landed in devbin 0.1.22's stack after 0331-1; unpushed until devbin's next cut, proved on its own arms under hv's rule of 2026-11-05 (red at the base's code, green at the fix) in one slot on devbin-vc's desk.

- install.switch and install.publish: a tool names its own switch and publish commands under its install: block, each as written, and one with no words is refused. cfg_tool_own <switch|publish> is the one reader, and cfg_tool_verb <switch|publish> the command a remedy names: the tool's own, else bin/devbin use or bin/devbin install.
- In a tool's checkout that declares install.switch, bin/devbin use refuses, bare or with a tree, naming the command, and points no link; its help names the command. Where install.publish is declared, bin/devbin install's opt publish refuses, naming the command, and writes nothing. --managed-by brew, the formula's publish into a keg, is not refused, since a keg is brew's tree, and --into vendors as before.
- The formula, doctor's rows and the link set still read install.links. Their remedies name the tool's own commands: doctor's switch rows, a split set, the left-off-brew note, a link into no tree of the tool and the opt tree's republish, and the cut's note back to brew names the tool's own switch.
- docs/dev-opt-brew.md's T2 and T5 say a tool may keep its own publish and switch by these keys. docs/configuration.md's install table and lib/config.reference.yaml carry both keys, and lib/pages/use.md and install.md the refusals.

Five new arms: four in tool.bats (the keys validate, their readers answer and an empty one is refused; use refuses bare and with each tree, pointing no link, its help naming the command; install refuses the opt publish, writing nothing, while --managed-by brew publishes into a keg; doctor's remedies for a split set and a drifted opt tree name both commands) and one in releasecut.bats (the note back to brew names the tool's own switch). All five were red at the base, each on its own finding. Twenty-two green legs, 46 arms, were green at the fix: tool.bats's arms over the tool's declaration, publish, use and doctor, the six arms that end on the note back to brew, documentation.bats's eight arms over the schema, the annotated reference and the configuration reference, and its two T4 arms. bin/devbin check lint at the fix was clean.
