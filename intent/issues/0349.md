## What happened

Ccusage's adoption of 0326 (reported by ccusage-dc, relayed by vc, 2026-11-13) found that Homebrew's build.rb (lines 232 to 236) moves metafiles (LICENSE, README, CHANGELOG and the like) out of `libexec` after install whenever the keg's root holds none. devbin's assets formula body moves the whole stage into `libexec`, so the keg's root holds none, and any metafile in a release archive leaves the manifest naming a file the keg does not hold. doctor then fails the tree row with `missing:` for each one.

## Why it matters

It affects new-form kegs too, not only the pre-contract ones in 0348: a tool cannot ship a LICENSE or README in its release archive without a brew install failing doctor. Ccusage now ships `bin/ccusage` alone to avoid it.

## Not yet known

The full list of names Homebrew treats as metafiles at the Homebrew version in use, and whether it changes between versions.

## Options, none chosen

- Have the formula body leave a metafile at the keg's root, so Homebrew moves nothing out of libexec.
- Have the manifest leave out, or the tree check pass over, files Homebrew moves, naming them.
- Have the release archive carry no metafile, and say so in the contract.

## Resolution

Fixed in one landing on main on 2026-11-13 at 09:45Z: unit 0349 at 363c4733241e294d18e596a61cf3b25c6aa11e4e. It was tested at the tip 47cc47df and rebased onto main with the same changed lines. It is in devbin 0.1.24's batch and stays unpushed until devbin's next cut.

- The first option is taken, by the mechanism devbin's own keg already relies on. Homebrew's build.rb (7.0.13) moves the buildpath's metafiles to the keg's root first, and moves libexec's out only when that leaves the root holding none. assets_ruby (lib/cmd/formula) now copies an archive packed at the install root into libexec (`libexec.mkpath`, then `cp_r Dir["*"], libexec, preserve: true`) instead of moving it. The stage keeps its metafiles for Homebrew's first move, and libexec keeps every file the manifest names. No list of Homebrew's names is copied into devbin, so "Not yet known" needs no answer here: whatever Homebrew counts as a metafile, it takes from the stage. An archive of bin/ alone is laid out as before. T8 in docs/dev-opt-brew.md says the stage is copied, never moved, and why.
- A keg that a 0.1.23 formula installed from an archive holding a metafile passes once the formula is rendered again and the keg reinstalled (`brew reinstall <tool>`), as doctor's row already says.

One arm in formula.bats runs the rendered install body under ruby_keg's new `meta` layout (LICENSE and README.md at the archive's root). libexec holds both, the manifest names both, and the stage keeps both for Homebrew's move. It was red at its parent, where the stage was left empty, and green at the fix. The brew style arm reads the new line and passes.

A real brew install, run once on devbin-vc's desk in the same slot, proves Homebrew's side. The rendered formula was installed from a hand-made tap under a scratch config: the keg's root held LICENSE and README.md, libexec held both, and every manifest line checked under shasum -a 256 -c. Doctor, run in the scratch project:

The check that caught it was wider than the claim, and devbin-vc accepted the dev row without a re-run. The clear-up left the machine as before: brew list --versions unchanged, the tap and keg gone, the trust file never written. 0.1.24's note carries 0349 under Fixed.
