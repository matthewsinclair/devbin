## What is wrong

`install.files` can only declare a runtime set file by file, or as a directory copied whole. The core's publish copies each place with a plain `cp -R` of its `from` (`lib/tool:274`), and `tool_runtime_set` (`lib/tool:144`) lists each declared place once. A place's `kind` is `tracked` when git tracks its `from` and `product` otherwise. So a directory entry ships everything beneath it: tests, untracked files from a dirty dev tree, and a build's links. Nothing lets an entry leave part of a directory out.

Two adoptions of devbin#0326 cannot declare their runtime sets with it:

- **Utilz (Utilz I59c806c).** The set is what git tracks under `bin opt help static VERSION`, less four things: `bin/devbin`, `bin/.devbin/`, each utility's `opt/*/test/` and `opt/prez/crate/`. To that go three build products of the prez crate (`opt/prez/crate/target/release/{prez,showreel}` and its `Cargo.toml`). That's 141 tracked files across 18 utilities at Utilz ST0031/01's tip. Per-file entries would be 141 labels that drift with every file added. An entry for `opt` ships every utility's tests.
- **Gtools (Gtools I7bd0048, gtools-dc's review R4).** Its set excludes `bin/devbin`, `bin/.devbin`, `bin/gtools_test` and `bin/help/gtools_test.md`. Under `native/cms/_build/prod/lib` it takes only `ebin/` and `priv/`, without the build's links into `deps/`.

Pplr and Cldr do not need it: each declares a binary and a file.

## Fix outline

An `install.files` entry may name a directory and carry `excludes:`, a list of globs relative to it. Its place in opt and brew then holds exactly what git tracks beneath its `from`, less what an exclude matches, at the same relative paths. Nothing untracked is copied, so a dirty dev tree's stray files never ship, and the publish's clean check (`_tool_publish_clean`) still reads the inputs against HEAD.

- A build product beneath such a directory, eg prez's binaries, is declared as its own entry, as today: kind `product`, copied as built.
- A product that is itself a directory, Gtools' `ebin/` and `priv/`, is copied whole with the same `excludes:`, and keeps no link that points outside it.
- `tool_runtime_set` and the manifest body stay one list: each file of a directory entry is a line of the manifest, sorted as T3 says, so doctor's drift check reads it unchanged.
- An exclude that matches nothing is named, so a renamed directory is not silently shipped whole.
- `docs/configuration.md`'s `install.files` rows and `docs/dev-opt-brew.md`'s T1 say the form.

The plan decides the glob grammar (bash `extglob`, or git pathspecs with `:(exclude)`, which git's own `ls-files` reads) and the key's name. It also decides how a tool's own reader of its runtime set, Utilz's `utilz_runtime_set` and Gtools' common.sh pathspecs, both of which compute `+dirty`, reads the declared set rather than keeping a second copy (gtools-dc's R6, Highlander). One answer is a read verb that prints the set, which a tool's dirty check calls.

## Done when

- A fixture project declares a directory entry with excludes. `bin/devbin install --prefix <scratch>` publishes exactly the tracked files less the excluded ones, plus the declared products, with a manifest naming each. An untracked file in the dev tree is not shipped, and an exclude matching nothing is named.
- Utilz's I59c806c and Gtools' I7bd0048 each declare their runtime set in a handful of entries.
- It ships in devbin 0.1.30 with I3ce05fa, so both adoptions vendor 0.1.30.
