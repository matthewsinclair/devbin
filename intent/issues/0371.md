## What happened

Found while 0352-1 made release_tag_version (lib/helpers) the reading of a tag back to its version, for release target and formula's tag_version. release_versions (lib/release.steps), which every bump and release_previous_tag read, matches a tag by the text before and after the template's first `{version}`, and takes what lies between as the version when it is an X.Y.Z. It never fills the template back, as release_tag_version does. So where release.tag holds `{version}` more than once, eg `v{version}-{version}`, a tag holding the text `{version}` itself, eg `v1.2.3-{version}`, reads as release 1.2.3, though no cut could make that tag. release_tag_version refuses it.

Neither reading can read such a template's real tags: the cut makes `v1.2.3-1.2.3`, which neither matches, so `--patch` finds no newest release. release.tag's value rule only asks that `{version}` appear, so it takes such a template.

## Why it matters

Two readings of one question give two answers, and release_versions is the one every bump reads. Low, since it takes a template with `{version}` twice and a tag holding braces pushed by hand.

## Options, none chosen

- release_versions reads each tag through release_tag_version, so the two cannot disagree.
- release.tag's value rule takes `{version}` once only, so no template has a second one to disagree over.

0352-1 left release_versions as it is, on vc's word that a reading that differs keeps its behaviour and is filed.
