version: 0.1.20
headline: a formula rendered in assets mode passes brew style, its install manifest's header written one element a line; and devbin's own release takes the core's standard shape, released from its public repository.
status: unreleased

**Why this release exists.** A formula that `formula render` or `formula publish` writes in assets mode wrote its install manifest's header as one Ruby line, longer than brew style's line limit, so a tap whose CI runs `brew style` or `brew audit --strict` went red on the formula devbin published (issue `0322`). This release fixes that. It also carries what devbin's main has held since 0.1.19: devbin's own release in the core's standard shape (issue `0320`), and its workroom, now public with the product. It keeps a 0.1 number, as 0.1.8 to 0.1.19 did, because every consuming project pins a `^0.1` caret.

## Fixed -- reaches every project

- **A formula rendered in assets mode passes `brew style` (issue `0322`).** The install manifest's header, the `lines = [...]` list the install body writes, was one line, 131 columns in one tap's render against brew style's `Layout/LineLength` limit of 118. It is now written one element a line, with the trailing comma brew's style asks for. The manifest a keg writes is byte for byte what it was, so nothing installed reads differently. In both modes, every line a render writes of its own, its header and the install body it generates, passes `brew style`, and a test holds every file a render writes to that where brew is installed. A tap that published an assets-mode formula with an earlier devbin passes once it publishes again with this one.

## Changed -- devbin's own tree

- **devbin releases from its public repository in the core's standard shape (issue `0320`).** Its config declares no `release.publish` or `release.snapshot`, and `release.remotes` names `local` then `upstream`. The cut pushes the release commit itself to `candidate/<tag>` on `upstream`, reads CI green there beside the local gates and the kovacs leg, then tags and pushes the commit and the tag to both remotes. The tag names the release commit, so the formula's revision is read from the tag in the checkout that cut it. `docs/releasing.md` says the same. The core's snapshot shape stays for any project that declares `release.publish.url`.
- **devbin's workroom is public with the product**: its `intent/` record, its own project commands under `bin/.devbin/`, and its agent instructions. None of it is in the set a project vendors.

## Known limitations

- **Every limitation 0.1.19's note names still stands**, except where an issue below says more.
- **`git_head_sha` reads a form it does not know as a short sha, silently (issue `0298`).**
- **`macos`'s commit-stamp check refuses a sha256 repository's 64-character stamp (issue `0299`).**
- **The release tests' fixture builders check no step, so a failure inside a command substitution reads as a project made (issue `0301`)**, and **the test harness lets git guess an identity, so an arm leaning on the guess is red only on a host without a domain (issue `0302`).**
- **`DEVBIN_TEST_JOBS` bounds the suite and nothing else, so a desk's core cap does not reach a project's build commands (issue `0303`).**
- **`worktrees` clears git's local variables silently before `remove-landed` writes (issue `0305`)**, where the release verbs name what they clear.
- **A cut's exit notes reach no log when the signal that ends it takes the tee and no person is at a terminal (issue `0307`).**
- **The candidate's remote pick passes over a url whose host cannot be read, so a mirror can take the candidate (issue `0310`).**
- **`macos`'s `drop_check_copy` restores only the traps `trap -p` printed, so a caller that saved INT alone would leave TERM and HUP ignored (issue `0311`).**
- **Pre-flight does not yet refuse a macOS stage whose build products or artefact path git does not ignore (issue `0313`)**; the stage and the local gates share the tree, so such a path fails a leg, blamed on the wrong one.
- **Under `derived:`, `--fires` is not given the stamp's known files, so a positive `paths:` filter can read quiet where the push would start a run (issue `0315`).**
- **`gate_spans` reads any name ending in `run_gate` as a gate call (issue `0316`).**
- **localinstall's `0059` FORWARD arm went red once on WSL 2, its publish reading a clean fixture source as dirty, cause unknown (issue `0318`).** WSL blocks no cut.
- **Switching a machine from opt to brew for one release makes every project's update notice speak, since the two installs name the release by two commits (issue `0319`)**, even where no vendored file would change.
- **Code that should be shared is still written twice in places (issues `0308`, `0309`, `0312`)**: a repository's host and OWNER/NAME split, the candidate ref's delete and read-back, and the lister of a commit's workflow runs.
- **Some comments in devbin's tree still say the public tree carries no `intent/` (issue `0321`)**, which the workroom's publication made untrue.
