version: 0.1.24
headline: a lanes run names each file's wall time and the load before its verdict, and a quiet gate's heartbeat says how far its command has got, with no terminal too
status: unreleased

**Why this release exists.** In 0.1.23's cut, a test run's output could sit still for half an hour and more while most of the suite had finished, because bats holds each file's results until every earlier file has printed: in CI's macOS log, 1761 s passed before one file's first result, and over half an hour on the next candidate, which was read as wedged. Nothing could say otherwise. The heartbeat beat only with a terminal attached and knew nothing of what its command had done, and the log held no time for any file and no load, so nobody could say which files cost a run its time, or what the machine was doing while it ran.

## Added

- **A lanes run names each file of its parallel lane with its wall time before its verdict (issue `0345`)**, the slowest first, and a file that failed with its exit. It then names the serial lane's time and the one-minute load average at the run's start and end. A file's time runs from its start to its end, any wait for a free job slot included. The verdict stays the run's last line, and the run's results pass through untouched. This covers devbin's own suite, `test shell` and a project's own runner that calls `"$DEVBIN_LIB/bats-lanes"`. Every bats the runner supports, 1.12 and 1.14, is timed; under a bats that starts its files any other way, the run runs as before and says it has no times.

## Changed -- a script or a config may get a different result

- **A quiet gate's heartbeat carries the progress its command writes, with no terminal attached too (issue `0346`).** Every gated command, eg `test`, `lint` and `release gates`, hands its command `DEVBIN_GATE_PROGRESS`, a file, as it hands `DEVBIN_GATE_LOG`. On each quiet beat the heartbeat adds the file's first line after the elapsed time, in the command's own words. A lanes run writes it as each file starts and ends, eg "the parallel lane: 37 of 69 files done (1210 of 3127 tests), 24 running". With no terminal the heartbeat beats only once the command has written a line, so a gate whose command writes none prints nothing new on stderr, as before. The beat goes only to stderr and never into the gate's log, so the TAP that a seal and its counts read is unchanged.

## Fixed -- reaches every project

- **T4's Rust reader of the version line, which every binary of a compiled tool carries word for word, builds clean under `cargo clippy -- -D warnings` in every edition (issue `0350`).** In an edition 2024 crate Clippy failed it three times on its nested `if let` blocks, so a tool that denies Clippy's warnings could not follow the contract as printed. It now reads the manifest as one chain of `Option` steps, with the same logic, and needs no let chain, which no edition before 2024 can build.

## Fixed -- devbin's own tree

- **`fleet upgrade`, `fleet audit` and `fleet doc` never walk into a directory named `_Archive`, at any depth (issue `0351`).** Each walked every directory under the roots, so a sweep upgraded an estate kept in an archive, and only a `DEVBIN_FLEET_FROZEN` set by hand on every run kept one out. The census now prunes each archive by rule and reads nothing in it. Every report names each one once: the sweep's not-swept table as `ARCHIVE -- not walked` with a count on its summary line, audit as a row of kind `archive`, and the document in a section of its own. The walk outside the roots prunes archives too, and says so with what else it does not walk.

## Known limitations

- **Every limitation 0.1.23's note names still stands**, except where an entry above says otherwise.
