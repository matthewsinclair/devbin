version: 0.1.16
date: 2026-10-29
headline: devbin can build a release's public snapshot and publish it through CI on that very commit, a new worktrees command says which linked worktrees are landed and removes them, a brewed devbin runs and answers help from a bare PATH and carries its guides, help pages answer for commands a project does not offer, version set writes only what it can prove it wrote, and install reads its directory arguments as typed.
status: released

**Why this release exists.** It carries everything since 0.1.15: issues `0238` to `0245` and `0251` to `0272`; `0246` to `0250` and `0273` move to 0.1.17. It is the first version made to be published: ST0010 makes devbin public as a new repository built from one audited snapshot commit per release, and this release builds that snapshot (`0239`), publishes it through CI (`0240`), and settles what it ships (`0241`, `0242`, `0261`). It keeps a 0.1 number, as 0.1.8 to 0.1.15 did, because every consuming project pins a `^0.1` caret.

## Added -- new commands, checks and routes

- **`release snapshot` makes a release's public snapshot, one deterministic commit over the list of what ships (issue `0239`).** `release snapshot <vX.Y.Z> <new-dir> [--no-parent]`, or `--commit <rev>` for an audit ahead of a cut, builds a commit holding exactly the files `release.snapshot.list` selects from the tag's tree, in a new repository outside the project, by git plumbing alone. Its author and committer are `release.snapshot.author`, its dates the source commit's at +0000, its message `release.snapshot.message`, and it is never signed, so the same release always makes the same sha. It is made on the tip of the publish branch, fetched first and refused unless every commit behind it is such a snapshot, made by the same identity; a first snapshot is made with `--no-parent`. A `release.publish.url` naming the repository one of the project's own remotes names is refused before anything is fetched. Every git call runs with git's local variables cleared and its hooks off.
- **`release publish` makes a release public through CI on the snapshot itself (issue `0240`).** `release publish <vX.Y.Z> [--expect <sha>] [--dry-run] [--yes]` builds the tag's snapshot, pushes it to `candidate/<tag>` on `release.publish.url`, waits for `ci.query` to read green on that sha, then fast-forwards the publish branch, pushes a lightweight tag, reads each back and deletes the candidate. Nothing is ever forced. `--expect` takes the whole sha an audit approved and refuses any other. A publish stopped part-way, or run again once finished, finds what is already public and carries on from there, and an older release run again after a later one is published is refused as public already.
- **`worktrees` reports each linked worktree as landed, held or unknown, with its evidence, and `worktrees remove-landed` removes the landed ones it is named (issue `0245`).** The report reads, for each worktree, its HEAD against `worktrees.branch` (default `main`), its own commits by patch-id, its staged and unstaged changes by patch-id and by content, against the branch and any bank refs `worktrees.banks` names, its untracked files and linked build targets, stash entries naming it, processes standing in it, and its lock. Plain directories beside the worktrees are listed with their size. `remove-landed` reads each named worktree again and refuses the main worktree, one gone, locked or stood in, the one the run itself runs from, and anything not landed; it runs a plain `git worktree remove`, never `--force`, and reports git's refusal as a finding. `--repo` reads another repository, report only. Every read is read-only, each worktree's index through a scratch copy.
- **`macos` signs an app that versions apart from its project, and checks the build it signs (issue `0243`).** `macos.version_from` names the file the app's own version is read from; an app that versions apart declares `macos.commit_stamp`, the Info.plist key its build writes its commit into, and `macos.kind_stamp` and `macos.kind_value` check the build's kind. Each is checked against the tag at `app-sign` and again at `publish`. A path key may open with `~`, `$HOME` or an XDG base-directory variable; any other leading form is refused, naming the key. Every copy `macos` makes has its Launch Services record dropped on every path out, interrupts included, and the record list is read back; after the upload, `publish` drops the records under `macos.build_root`, refusing a root that would sweep the home directory or an applications folder.

## Changed -- a script or a config may get a different result

- **A project that declares `release.publish.url` cuts to `release.remotes` alone, and stops after its push (issue `0240`).** A remote it would push to that names the publish repository is refused at pre-flight, so a cut never pushes the workroom's history to the public repository; the snapshot, candidate and publish rows wait on `release publish`. Without `publish.url` a cut runs as before. Under `publish.url` the formula's revision is the public tag's commit, and the formula template's url is https. CI runs on `candidate/**` pushes, the macOS and WSL legs included, as on a tag.
- **A built-in the project does not offer answers `--help` and `-h` as `help <cmd>` does, and running it names that page (issues `0255`, `0271`).** `help <cmd>` prints devbin's page for a built-in this project does not offer, at exit 0, under a line saying why it is not offered and what would offer it, where it refused as if the command did not exist. `<cmd> --help` and `<cmd> -h`, in any position, answer the same way and read none of the other arguments, and the refusal of a run ends `(its page: bin/devbin help <cmd>)`. A command devbin does not ship is still refused, at exit 2.
- **From a machine install, help answers, and `devbin devbin` says what an install is (issue `0251`).** A bare `devbin`, `-h`, `--help`, `help` and `devbin devbin` were refused at exit 5 outside a project, so nobody could read how to seed one before seeding it. The upgrade remedy names `--from` only where the machine does not already name the install.
- **On macOS a brewed devbin runs from a PATH without Homebrew's bin, as cron or a GUI-started hook has (issues `0253`, `0266`).** The keg's `bin/devbin` is a script that puts the formula's bash first on PATH, so macOS's bash 3.2 never refuses it, and every path devbin prints for a keg names that `bin/devbin` through Homebrew's opt link, never the launcher inside the keg. The bash floor's refusal names a bash 5 the machine has, and tells only a machine with none to install one. `use brew` reads the keg's `bin/devbin` as Homebrew's whether it is a link or that script.
- **A brew install carries devbin's guides beside its README, and every message naming a guide names its path on this machine (issue `0254`).** The formula installs `docs/`, `RELEASES/` and `RELEASES.md` in the keg. `devbin devbin` and `release --help` name the guides where they are: in a checkout, in a keg, or, for a project, in the install its upgrades read; an opt install says it carries none.
- **The version line's sha field is always twelve hex digits, then `+dirty`, or `unknown` (issue `0244`).** A recorded commit of seven to eleven digits printed short, and a 64-digit one printed its first twelve and then its digits from the 41st on; one of fewer than twelve now prints `unknown`.
- **`install --into` refuses a target that is not a directory, saying what is there, and an empty `--into` is refused by name (issues `0258`, `0268`).** A file, a link to nothing and a quoted `~` are named as what they are, and a path with nothing at it gets a `mkdir -p` line to paste. `--into ""` read as no `--into`, and vendored a machine install into the current directory at exit 0.
- **infra's machine-wide profile follows `XDG_CONFIG_HOME` (issue `0272`):** `$XDG_CONFIG_HOME/devbin/infra.yaml` when that is absolute, `~/.config/devbin/infra.yaml` otherwise.
- **devbin finds PlistBuddy on PATH first, then at macOS's own `/usr/libexec/PlistBuddy` (issue `0264`)**, as it finds every other tool it runs.
- **The exit-code contract is stated once, in `docs/authoring-commands.md` (issue `0241`)**, which now lists exit 6 and why a new refusal takes a new code.

## Fixed -- reaches every project

- **A version that does not read is never passed on as one (issue `0259`).** With no version file, `version show` printed `unknown` at exit 0 and `version check` passed. Now `show`, `check`, `bump` and `sync` refuse, naming the file, the key that names it and a remedy, `doctor` notes it, `version set 0.1.0` starts a missing bare version file, and a release cut refuses at pre-flight.
- **`version set` refuses, before it writes anything, every file its write could not change (issue `0260`)**, so a file with no version devbin reads, or one it cannot write, no longer leaves the files before it at the new version. A sidecar devbin cannot read is refused, never taken as empty and overwritten.
- **Each structured recipe rewrites the one line devbin reads the version from, and no other (issue `0263`).** `version set` rewrote every version-shaped line of a `Cargo.toml`, a dependency table's included, and a nested `"version"` in a `package.json` and a second `version:` in a `mix.exs` alike. A manifest that gives its version another way, such as `version.workspace = true`, is refused.
- **`set`, `bump` and `sync` read every file back after writing it, and refuse unless each reads the version written (issue `0264`).** PlistBuddy exits 0 when it cannot write, so a plist could stay at the old version while `set` exited 0.
- **One classifier says what stands at a version file or a sidecar, and one table words each state, for `set`, `check`, `show` and `doctor` alike (issue `0265`).** `check` no longer prescribes for a missing sidecar the `sync` that refuses it.
- **install, upgrade, vendor and release read a directory argument as typed, never through `CDPATH` or as `$OLDPWD` (issue `0267`).** Under an exported `CDPATH`, or given `-`, install wrote the project under a path holding a newline, at exit 0. `bin/devbin` itself, typed at a project root under such a `CDPATH`, found no runtime. `macos` places its stage as the filesystem spells it, so a stage holding `..` or typed in another case is read as inside the project and refused.
- **Hints from a Homebrew install name devbin's launcher as you would type it, never the versioned keg (issue `0252`)**, which the next `brew upgrade` deletes, so an rc line copied from shell-init no longer breaks the shell then.
- **A rendered formula, and its cask, open with a header of the render's own, naming the template, the tag and the commit (issue `0257`)**, in place of the template's, which says the file is never installed from.
- **The README's and shell-init's `dvb install` examples make the project's directory before changing into it (issues `0258`, `0269`)**, and the README's command tables list what a freshly seeded project offers (issue `0256`).

## Fixed -- devbin's own tree

- **Test Summary names a CI leg GitHub never ran on a line of its own, apart from the legs that failed (issue `0238`)**; the step still fails, since a required leg with no verdict is no pass.
- **The public snapshot ships the product alone, and names no project of the owner's but Intent, Molt and Utilz (issues `0241`, `0242`).** It leaves `usage-rules.md`, `.intent_critic.yml` and `.prettierignore` in the workroom, and a workroom arm refuses, in any shipped line, the names on a list that does not ship.
- **`tests/shipped.paths` has one reader, which knows every exclude spelling git accepts (issue `0261`)**, for the snapshot builder and the workroom scan alike.
- **One predicate answers whether a tree is a machine install, and every reader asks it (issue `0262`).**
- **Every test builds a Homebrew keg through one builder, `brew_keg` (issue `0270`)**, so a change to the formula's layout is followed in one place, and a harness arm refuses a keg built any other way.
- **`bin/devbin test --failed` reruns only the tests the last bats run failed**, as `mix test --failed` does, from the newest seal under `tmp/test/`.

## Known limitations

- **devbin is not public yet.** `release snapshot` and `release publish` are built and tested against local repositories, and ST0010's audit, its approval and the first publication come after this cut. Until then the repository and the Homebrew tap stay private, so `brew install` needs GitHub credentials on every machine.
- **`version check` words an empty sidecar as `empty (expected <version>)` in its drift line, a second wording of the empty state (issue `0265`).**
- **`worktrees` does not see a process of another user it cannot read, and does not say when one bank ref carries more than one patch (issue `0245`).**
- **The built-in `macos` has not yet signed or notarised a real app (issues `0226`, `0243`).** Its arms run against stand-ins for `security`, `codesign`, `xcrun`, `spctl` and `lsregister`.
- **CI green before the cut proves the base commit on the Tests workflow's summary (issue `0223`)**, and `release.ci.base` is refused under `release.publish.url`, where CI on the candidate is the gate.
- **On a forward move of the source, doctor's source row, the update notice and the offer compare the vendored set's bytes, which takes far longer than comparing commits (issue `0224`).** The notice asks at most once a day on a terminal.
- **`-only-testing` matches a type name, and devbin does not resolve a swift-testing display name to its type (issue `0229`)**; the empty-run refusal is where such a filter shows.
- **ST0008 is not finished, and devbin does not run natively on Windows.** AC-2.1's clause on WSL 2 behind a VPN is not yet measured, and AC-6.4, an adopting project running the smoke list in WSL, is not yet received. The WSL leg is a CI runner's WSL 2, and the smoke list's server is a stub.
- **The smoke list asserts the critic gate on the fixture carrying `intent/` by `check all`'s exit alone (ST0008 WP-06).**
- **A project's name has no shape, so no test holds the vendored set to naming none (issue `0202`)**; review holds it, and the workroom's names arm holds the owner's projects.
- **`text_shown` prints a url whose password holds a raw `/` (issue `0218`)**, a malformed url, as it stands.
- **An interceptor that forges AA is read as the zone's own answer, and the interception probe proves only what reaches TEST-NET-2 (issue `0193`).**
- **`infra` follows no CNAME (issue `0196`).**
- **Each remote has its own read-back in the push step, so a remote that does not answer holds a cut for over two minutes (issue `0194`).**
- **Install's line-ending block gives a project's newline-less last line a newline, and converts no file already carrying CR bytes (ST0008 WP-01).** doctor names each such file.
- **Some of devbin's own test files still build their fixtures per test (issue `0192`).**
- **`fullcycle.bats`'s slow-y arm reads a charged wait green when the time around the prompt passes a few seconds (issue `0199`)**, so under load it can miss a regression of `0096`.
- **`fullcycle`'s artefact check reads a `release/` it cannot list as holding no binary (issue `0177`)**; it fails closed, at rc 1.
- **Where git cannot say, whether a repository is there is read from the filesystem, and some cases read otherwise than git would (issues `0179`, `0185`).**
- **`vendor` does not refuse a devbin that is no checkout and has no manifest (issue `0178`)**; `upgrade` refuses one.
- **A check `check lint` runs again alone is not always alone, and nothing times a check out (issue `0184`).**
- **The release pre-flight still refuses a `tmp/` committed as a link outside the tree, and an untracked link on that path (issue `0186`).**
- **devbin's own `docs/authoring-commands.md` still recommends `postgresql://user:$PGPASSWORD@host/db`, and some arms plant the shape (issue `0187`)**; a vendoring project carries only the vendored set, which is clean.
- **A dry run's `no step failed` speaks for the steps it reaches (issue `0181`)**; the NOT REACHED list names the rest.
- **`release` leaves out of a url only what it can read as a userinfo (issues `0188`, `0189`).**
- **A manifest written before 0.1.9 keeps its recorded path through that project's first upgrade from a runtime older than 0.1.9 (issue `0153`).**
- **A project's own `.gitignore` in a gate's log directory is left as it is, even one that ignores nothing (issue `0157`).**
- **The cargo config order `check targetdir` and `fullcycle` read is cargo 1.99.0's as measured (issue `0164`).**
- **`check targetdir` does not see a cargo config inside a directory `find` cannot read (issues `0145`, `0163`)**, and a nested `clean` never removes `<root>/target` for a crate with no root `Cargo.toml` (issue `0167`).
- **`fullcycle`'s artefact check does not see a release lost while another was built, and does not read custom profiles (issue `0168`).**
- **cargo is asked from each crate's own directory (issue `0150`).**
- **The lint arm skips where shellcheck is not installed (issue `0155`)**, and no test holds the refusal of an explicit empty `senders.*.dkim.type` (issue `0161`).
- **A commented key in the reference config with prose directly above and below it reads as prose to the schema check (issue `0173`).**
- **The neutrality tests do not read a citation or a count split across two lines, nor a line opening with `#` inside a heredoc (issue `0172`).**
- **The `MIX_ENV=prod` refusal does not reach a project's own `db` handler (issue `0132`).**
- **The shipped pages are checked for prettier stability only where prettier is installed.**
- **`infra` checks DNS and mail records only.** The Fly runtime and `infra mail dmarc check` are devbin's ST0006, which is not built.
- **Intent and one other project still release with their own orchestrators.**
- **The vendored-set scans fold case in ASCII letters only (issue `0205`).**
- **The arm that holds a runtime to one digest under every locale runs where the runner has an en_US UTF-8 locale (issue `0204`).**
- **Assets reach a release after it is published, which works while immutable releases are off (ST0008 WP-08)**, and `release status` and `release attach` read a release's assets as consistent, not as complete.
- **An attach reads its assets from the run's artifacts, which GitHub keeps for a limited time, and each call to GitHub is cut off at a fixed bound (ST0008 WP-08).**
- **The release core's reads before the first push are not time-limited**, nor is `release status`.
- **A cut under `object: ci` depends on the project's workflow running.** If CI does not start a job, the tag and the pushes stand and the object step fails at `object_wait`.
