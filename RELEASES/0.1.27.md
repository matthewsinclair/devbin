version: 0.1.27
headline: `release target` gives a CI workflow its release's version and tag; a cut's pre-flight on macOS asks `macos doctor` before anything is stamped; a write under `release.unread` no longer fails a cut's gates; a run a signal ended still closes when its output has no reader; and `use` says when an open shell needs `rehash`
status: unreleased

**Why this release exists.** It ships everything on main since 0.1.26: fixes for fourteen issues, most met in a cut. A CI workflow the candidate's push started could not read the release's version or tag, so a binary it built stamped itself `dev`. A Developer ID identity or a notary profile gone bad was found only at the macOS stage, after the release commit. A board write by another session in a shared checkout failed a cut's gates as if a gate had written it, and a commit landing after the release commit failed the cut only after every gate had run. A gate run ended by a signal could die of SIGPIPE with no verdict. A cut that stopped red left its remote legs' runs on their hosts. And `--help` after a declared option of a project's own command ran the option.

## Added

- **`release target` prints the release's version and tag as the tree declares them (issue `0352`).** It prints `DEVBIN_RELEASE_VERSION=<version>` and `DEVBIN_RELEASE_TARGET_TAG=<tag>`, the lines a CI environment file takes, so a workflow the candidate's push starts can read the target the rest of the cut reads. With `--ref <ref>`, the ref the run was started by, it prints them only for this release's candidate or its tag; any other ref prints nothing and exits 0, saying so on stderr, and a candidate branch made from another release's tag is refused, naming both. It writes nothing, takes no lock and reads no history. It joins `release.verbs`' default.
- **`release.unread` names paths no gate and no pre-flight command reads (issue `0355`).** It is empty by default. A path under it is left out of every read a release makes of the tree: the `+dirty` stamp, the gates' seal, pre-flight's tree rule, the stamp step and the re-reads after each gate and each pre-flight command. So another session's write there while a cut runs no longer fails it, and the release commit never holds such a path, even one a peer staged. Each read names what it left out. A path the release itself owns under the list is refused. A path is matched as git matches a literal pathspec from the top, a whole segment at a time.
- **`gate_signals_arm`, `gate_progress_file` and `gate_signal_close` (`lib/runlog`) are the signal handling `run_gate` does, as three functions (issue `0359`).** A project's handler that runs a gated tool without `run_gate` calls them, rather than copying the traps, the progress file's name, the exit for a signal and the `ENDED BY SIG...` line. `run_gate` calls them too, and behaves as before.

## Changed -- a script or a config may get a different result

- **A cut's pre-flight on macOS runs `macos doctor` where the macOS stage is declared (issue `0366`).** It goes through the project's launcher, as the stage's own `macos leg` does, so a project's own `macos` answers it. A doctor that exits non-zero refuses the cut before anything is stamped, naming each of its MISSING, NOT USABLE, FAILED and REFUSED lines. Like the stage, it asks Apple: a test-sign's timestamp and a notarytool query. A project with no macOS stage, or a host that is not macOS, is not asked.
- **The release gates refuse to start at a HEAD that is not the commit they were started for (issue `0355`).** A commit landing after the cut chose its release commit now stops the local gates before any runs, naming both commits, where every gate ran and the cut then failed naming no cause. The refusals that blamed a gate or a pre-flight command for a tree change or a HEAD move now say what moved, and that a gate, the command or another session in this checkout moved it.
- **`-h` or `--help` after a declared option of any command prints `help <command>` and runs nothing (issue `0370`).** 0.1.26 answered the flag in any position only for devbin's six gate commands, so a project command's declared option was handed the flag as a word of its `run:` line and ran. A command-level `run:` line, a project's handler and devbin's own built-ins other than the gates still read their own flag. A declared option's tool that takes `-h` or `--help` as a word of its own no longer gets it from the command line.
- **A `release.gates` entry whose first word is `release` is refused as config (issue `0364`)**, as a pre-flight command's already was, since it would run the gates again from inside themselves, or start a cut inside the cut.
- **`release.tag` takes `{version}` once (issue `0371`).** A template holding it twice is refused at validation, since a tag made from it reads back to no version and no bump could find it. Every reading of a tag back to its version, a bump's and `release_previous_tag`'s included, now goes through one function.

## Fixed -- reaches every project

- **A gate run a signal ended still closes when its output has no reader (issue `0360`).** Where both streams went to one pipe, eg `2>&1 | tee`, a signal to the whole group could end the pipe's reader, and the run died of SIGPIPE, 141, with no verdict, no ledger row and its in-flight marker left as its seal. `run_gate` now ignores SIGPIPE for its own shell from before the pipeline, while the gated command and everything it starts keep it as they had it. Under a caller's `errexit`, a failed write after a signal no longer ends the run before its close: errexit stays off to the close and comes back as the run returns. And a run a signal ended reports from a subshell, so the failed writes of its close are not written again as the caller exits.
- **A leg's start clears the project's ended runs at other commits from its host (issue `0367`).** A run on a leg's host was cleared only by a read that found it ended, so a cut that stopped red, then re-cut at another commit, left the first run's worktree, log, status and `TMPDIR` on the host. Each start now copies each such run's log back, then clears it. A run with no exit status, still going or killed before it wrote one, is left as it stands, and so is the run at the start's own commit. A listing or a copy that fails is warned of, and the start goes on.
- **A bounded call has a `TMPDIR` of its own, removed when it ends (issue `0368`)**, the deadline's kill included, so a call killed at its bound leaves nothing in the caller's `TMPDIR`, in a cut as in a suite.
- **`use` ends a switch that makes or removes a link with the line an open shell needs (issue `0354`).** zsh and bash keep the path they first ran a command from, so after a switch an open shell could still run the old copy. `use`, devbin's own and a tool's, now names the links it made and removed and says to run `rehash` (zsh) or `hash -r` (bash). A link repointed needs neither and draws no line.
- **`infra`'s handle advisory accepts the whole names `infra init` writes (issue `0363`).** Where two domains in a profile share a first label, `init` keys each by its whole name with the dots dashed, and the advisory flagged those very handles as not derived from their names on every run. One function now gives that form to both.
- **The overview's guide line lists every guide `docs/` holds (issue `0358`)**, read from the directory rather than written out by hand, where it named four of the six. docs/configuration.md's release step 6 says every artefact the `build:` block declares gets a `cache` line on the seal, not the macOS stage's alone, and `new`'s page says what its stub search passes over (issue `0362`).
- **The docs name each built-in a cut reaches through the project's launcher (issue `0365`):** `version set`, `ci-state`, `macos leg` and its sign and notarise verbs, `macos doctor`, `publish`, `bin-publish`, `release attach` and `formula publish`. A project command at one of those names replaces the built-in in the cut too, as it does when a person runs it.

## Changed -- devbin's own tree

- **devbin's own config declares `release.unread` as `intent/whiteboard` and `intent/.canon/events`**, the board and event files other sessions write in its shared checkout while a cut runs.
- **Each test has a `TMPDIR` of its own (issue `0368`)**, removed with the test, as it already had its own `CARGO_HOME`, `XDG_DATA_HOME` and `HOMEBREW_PREFIX`, so a whole run leaves nothing at the top of the `TMPDIR` it was started with.
- **helpers.bats' `traps_restore` arm uses USR2 in HUP's place (issue `0369`)**, since a suite started under `nohup` inherits HUP ignored and cannot trap it, and the arm failed on its launch rather than on the code.

## Known limitations

- **Every limitation 0.1.26's note names still stands**, except where an entry above says otherwise: a workflow the candidate's push starts can now read its target with `release target` (`0352`), a write under `release.unread` no longer fails the gates (`0355`), a run a signal ended closes (`0360`), `use` says when to rehash (`0354`), `run_gate`'s signal handling is three functions a handler can call (`0359`), and the two docs that lagged the code are fixed (`0358`).
- **A CI workflow still has to ask for its target.** The cut does not hand the version and tag to a workflow its candidate's push starts; the workflow runs `release target --ref <its ref>` and takes the lines into its environment.
- **The macOS stage's build, and the signing of the release's own commit, stay unrehearsed.** `macos doctor` at pre-flight reads the identity and the notary profile, and their first real run is still the cut's.
- **A project's own `macos.build` that stamps `+dirty` from its own read of git is outside `release.unread`'s reach.** The stage passes such a tree, and the build's own stamp may still read dirty.
- **0326's adoptions follow in Pplr and Cldr**, under pplr#0001 and cldr#0001, on each project's own word; until then their own copies stand.
