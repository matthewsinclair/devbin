## Changed

- **Every hand-written doc was audited against the code as built, and corrected where they disagreed.** README, `docs/` (configuration, authoring commands, migration, releasing), every command's help under `bin/.devbin/help/`, the annotated config and infra references, and the project's architecture, module and rule notes. Among the corrections: a release dry run runs every gate for real on HEAD, `test all` included, and writes their run logs under the ignored `tmp/` (the docs said it wrote nothing); the release CI wait's floor is 15 seconds, not 5; the release note's format is written down; a project's `project.referent` runs without git's optional lock; and the retired project-named launcher is gone from the examples. The one-line descriptions in the command catalogue, the usage text and the source comments were corrected in the same pass.
- **A devbin install refuses to run a project command with exit 5, its own code (issue `0099`).** It exited 3, which is reserved for a command that resolves but is not implemented, so a script could not tell the two apart. Anything that tested for 3 from an install tree must test for 5.
- **`install` and `upgrade` refuse a flag that does not apply to their mode (issue `0103`).** `install` refuses `--force`, `--name`, `--alias` and `--lang` when it publishes; `upgrade` refuses `--from` and `--force` in devbin's own tree and `--prefix` in a project. Each was silently ignored before.
- **Validation refuses a whitespace-only release command line (issue `0104`).** `release.ci.query` and every `derived:`, `after:` and `gates:` item now meet the same no-words rule as every other command line, so `doctor` reports one, where before only the cut refused it at its step.

## Fixed

- **`enabled: false` hides a project handler from help, as the dispatcher already refused it (issue `0097`).**
- **`help --why` names an option the project declared and switched off (issue `0098`).** `all`'s count line promised it did.
- **`fullcycle`'s consent line is tagged as devbin's own (issue `0100`),** so the run's seal strips it before any grammar reads the log.
- **`fleet upgrade` names every worktree and dependency checkout it leaves out, with a count (issue `0101`),** instead of dropping them silently, as `fleet audit` and `fleet doc` already did. Its summary line gains `, N not an estate`, so anything that parses that line sees the new clause.
- **`upgrade` counts released files apart from edited ones, each with its own remedy (issue `0102`).** It advised `--force` for a released file, which `--force` can never reach. The summary line's shape is unchanged, because `fleet upgrade` reads it across versions.
- **`new` writes `bin/devbin` into the files it scaffolds (issue `0105`),** never the absolute path it was called by from a subdirectory.

## Known limitations

- **Intent and one other project still release with their own orchestrators, and Utilz has declared the release core but not yet cut with it.** The adoption continues in each project's own work.
- **`fullcycle`'s overhead is measured across the whole cycle, not per phase.**
- **The release core's reads before the first push are not time-limited**, nor is `release status`.
- **A cut under `object: ci` depends on the project's workflow running.** If CI does not start a job, the tag and the pushes stand and the object step fails at `object_wait`; the workflow's run for the tag has to be re-run before the cut can finish.
