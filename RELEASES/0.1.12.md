version: 0.1.12
date: 2026-10-17
headline: devbin's shipped code names no project and its worked examples use reserved names, a cut publishes the Homebrew formula as its after: step, and CI runs the suite and a smoke list inside WSL 2 on a Windows runner.
status: released

**Why this release exists.** It carries everything since 0.1.11: issue `0202`, closed, and the last two of ST0008's seven work packages, WP-05 and WP-06, with ST0009's formula publishing. ST0008 is not closed: two acceptance criteria wait on things outside this repository (see Known limitations). Most of what reaches a consuming project is wording: `0202` came from another project's reading of 0.1.11, and devbin is to go public, so its vendored files now name no project and say nothing of how devbin was decided. It keeps a 0.1 number, as 0.1.8 to 0.1.11 did, because every consuming project pins a `^0.1` caret.

## Rolling it out -- a one-time effect on every project

- **The sweep that rolls 0.1.12 out is the later upgrade 0.1.11's note named, so it writes `.gitattributes` in every project that has no devbin block yet (ST0008 WP-01).** Each project's upgrade to 0.1.12 is run by the 0.1.11 runtime it vendors, which writes devbin's line-ending block into the project's root `.gitattributes`, creating the file where there is none. That sweep's commit pathspec needs `.gitattributes` beside `bin/devbin` and `bin/.devbin/`, or it leaves every project dirty.

## Changed -- a script or a config may get a different result

- **The infra reference profile's worked example uses a placeholder sender under `.example` (issue `0202`).** `lib/infra.reference.yaml`'s labelled-DKIM sender named a real mail provider; it is now `transactional`, with `_spf.transactional.example` and the records `tx1` and `tx2`, and the domain `partner` names it. A profile copied from the reference before 0.1.12 is unaffected; one copied after it carries the placeholder, which a person replaces with their own sender, as every other value in the example.

## Fixed -- reaches every project

- **devbin's vendored files name no project and carry no decision language (issue `0202`).** `lib/install`'s comment on refusing to write into a keg named another project as its precedent; it now says another tool's `--managed-by brew`. Twenty-five comment lines across `bin/devbin`, `lib/cmd/check`, `clean`, `infra` and `upgrade`, `lib/helpers`, `lib/infra.check`, `lib/infra.init`, `lib/resolve` and `lib/runlog` described how devbin was decided rather than what the code does, and each now says what the code does. `lib/infra`'s comments describe the reference profile's sender generically. No behaviour changes.

## Fixed -- devbin's own tree

- **devbin's release publishes its Homebrew formula as its `after:` step (ST0009).** `bin/.devbin/config.yaml` declares `after: bin/devbin formula publish`, which the core runs past step 8's push, so the tap never names a tag brew cannot fetch; a publish that fails is step 10's FAILED row, the release stands, and the cut exits 1 naming the command. Two `releasecut.bats` arms cut a fixture with this repository's own `after:` list against a local tap, one publishing after the push and one refused by the tap. `docs/releasing.md` and the `formula` page no longer say the tap does not exist.
- **CI runs devbin's suite and a smoke list inside WSL 2 on a Windows runner, on release tags and on demand (ST0008 WP-06).** The job runs Ubuntu 26.04 under WSL 2 as a non-root user, from a clone in WSL's own filesystem, names the WSL version it asked for and fails if the kernel disagrees, and refuses to run as root by name before the suite. It runs `bin/devbin test all`, installs Intent's Linux package from Intent's public release at a pinned tag and sha256, and runs `.github/wsl-smoke.sh`: on two fixture projects built from nothing, one carrying `intent/`, it runs shell-init bash and `dvb`, check all, test all, a server started and stopped, package, contract, version check, clean and help. Test Summary does not wait for it, so it blocks no release. Its first green run passed 2392 tests and all 18 smoke steps. `ci-workflow.bats` holds the job's gate, its absence from the summary, its version in the name, its one root step and its steps inside WSL.
- **The suite passes under uutils' coreutils, with no change needed (ST0008 WP-05).** Measured on Ubuntu 26.04.1 on aarch64 with uutils coreutils 0.10.0: its one failure was fixed in 0.1.11 as `0198`, and the run at 0.1.11's release head passed 2384 of 2384. 0.1.11's note said WP-05 had not started; it closed on those runs.
- **`neutral.bats` holds the vendored set to no decision language and the vendored reference profiles to reserved example domains (issue `0202`).** One arm refuses the past tense and the noun forms of "rule" used for a decision, any case, on every vendored line, comments included; another refuses, in the vendored reference yamls, a domain under a common public suffix unless it is `example.com`, `.net` or `.org` or under one. Each plants a positive and a negative control before it reads the tree.

## Known limitations

- **ST0008 is not finished, and devbin does not run natively on Windows.** AC-2.1's clause on WSL 2 behind a VPN is not yet measured, and waits on a real Windows machine (Intent's ST0082). AC-6.4, an adopting project running the smoke list on one of its own repositories inside WSL, is not yet received. The WSL leg is a CI runner's WSL 2, not a developer's machine, and the smoke list's server is a stub that writes a marker and sleeps, not a real application server.
- **The smoke list asserts the critic gate on the fixture carrying `intent/` by `check all`'s exit alone (ST0008 WP-06).** The gate is active there by construction, but its own lines stay in the job's `smoke.log` inside WSL and are not readable from CI.
- **A project's name has no shape, so no test holds the vendored set to naming none (issue `0202`)**; review holds it. The domain arm reads only the vendored reference yamls.
- **The Homebrew tap is private while devbin's repository is, and the formula's url is `ssh://` (ST0009)**, so `brew install` needs a GitHub ssh key on every machine. `brew upgrade devbin` from 0.1.11 to this release is proven only after this cut, on the operator's machines (issue `0201`).
- **A first publish to a linked spelling of `install.prefix` is refused `--point` (issue `0197`)**, and no arm runs a `fleet` sweep with `--apply` end to end on a brew machine.
- **An interceptor that forges AA is read as the zone's own answer, and the interception probe proves only what reaches TEST-NET-2 (issue `0193`)**, so a path that intercepts only some addresses leaves its replies without AA unexplained, though every read still says what came back.
- **`infra` follows no CNAME (issue `0196`).** A CNAME inside the zone whose target has no record of the type asked reads NOT MEASURED rather than as the absence it is, and for a chain of CNAMEs the line names the first hop, not the end of the chain.
- **Each remote has its own step 8 read-back, so two remotes that do not answer hold a cut for about 135 s each (issue `0194`)**, and a failure to make the read-back's scratch directory reads as a read-back that waited.
- **Install's line-ending block gives a project's newline-less last line a newline, since the block cannot follow it otherwise, and converts no file already carrying CR bytes (ST0008 WP-01).** doctor names each such file, and the fix is the operator's: `dos2unix`, or `upgrade --force` for a vendored one. Intent writes its own block for its hooks; devbin writes none for it.
- **A Windows shim with no extension, found where the Linux tool is missing, is not modelled by the Windows PATH arms (ST0008 WP-04)**; the runtime runs no such tool, and a missing Linux tool is already reported by `require` and the hints.
- **Two of devbin's own test files still build their fixtures per test (issue `0192`):** `upgradeoffer.bats`'s publish history and `releasecut.bats`'s project and remote carry each test's own directory in committed config, so a copy would not be the state a fresh build gives. Every file builds both caches in `setup_file`, including the ones that never install.
- **`fullcycle.bats`'s slow-y arm reads a charged wait green when the time before the prompt and after the gate passes about 3 s (issue `0199`)**, which load can cause, so on such a run it misses a regression of `0096` rather than reporting a false one.
- **`fullcycle`'s artefact check reads a `release/` it cannot list as holding no binary (issue `0177`).** Where a build tree cannot be listed and neither can its `release/`, the tree's warning and the summary's line for a tree listed while its own `release/` held no binary both say that `release/` holds no binary, which the check cannot know; the warning that it cannot be listed prints beside them. A tree that comes back between the check's tests reads as one it cannot search, or as one behind a link that cannot be followed exactly. Both fail closed, at rc 1.
- **Where git cannot say, whether a repository is there is read from the filesystem, and four cases read otherwise than git would (issues `0179`, `0185`).** A `.git` past a filesystem boundary still counts, where git's discovery stops; so does a `.git` git passes over, an empty `.git` directory or a dangling `.git` link; `GIT_CEILING_DIRECTORIES` is read only to its first newline, so a ceiling listed after one is not honoured; and a bare repository counts as none. So `fleet` reads a root whose only `.git` sits above it, past a filesystem boundary or past a ceiling listed after a newline, as `not its own checkout`, where 0.1.9 said `not a checkout`. With no git on `PATH`, a gate's log directory in a repository gets no ignore file, and the run says git could not say whether it is tracked, with no line from git; 0.1.9 wrote the file there unannounced.
- **`vendor` does not refuse a devbin that is no checkout and has no manifest, so it names no variable there (issue `0178`)**, as in 0.1.9; `upgrade` refuses one, naming `DEVBIN_INSTALL_PREFIX` where the variable placed it.
- **One frozen name freezes two projects where the same path sits under two roots (issue `0182`)**, since both carry one label. 0.1.9 froze by basename, so a bare name froze every project of that name.
- **A check `check lint` runs again alone is not always alone, and nothing times a check out (issue `0184`).** A check whose worker was killed can still be running when its file's second run starts; the second runs go one at a time; and a check that never returns holds the gate, in the second run as in the parallel run. That holds on every xargs now, where on GNU xargs 4.9.0 0.1.9 stopped waiting once a worker was killed by a signal (issue `0180`). The parallel run is still sized by CPUs, never by free memory. A lint gate killed outright leaves its scratch, and its workers finish into it; nothing in devbin kills the gate.
- **The release pre-flight still refuses a `tmp/` committed as a link to a directory outside the tree, as 0.1.9 did, and an untracked link on that path inside the tree (issue `0186`).** A `tmp/` that is a submodule passes until `tmp/release/` holds a `.gitignore` of its own, as after a run has written there, and is then refused, with git's `is in submodule` line, where 0.1.9 said `add tmp/ to .gitignore`. `--version` prints the bare commit over a tree whose status answered after skipping a directory it could not open, as 0.1.9 did.
- **devbin's own `docs/authoring-commands.md` still recommends `postgresql://user:$PGPASSWORD@host/db`, and arms in `gendoc.bats` and `neutral.bats` plant the shape (issue `0187`)**, so a secret scanner over devbin's own repository can find them; a project that vendors devbin carries only the vendored set, which is clean.
- **A dry run's `no step failed` speaks for the steps it reaches (issue `0181`)**; the NOT REACHED list above it names what it could not predict.
- **`release` leaves out of a url only what it can read as a userinfo (issues `0188`, `0189`).** A url it cannot read that way reaches its refusals and git's words whole, as one holding a raw `/` in its userinfo does where the url has no scheme, where no `:` stands ahead of that `/`, or where the password runs only digits up to it. Where a raw `/` follows a raw @ in the password, the userinfo ends at that @, as git reads it, and the rest of the password reaches them as the host and the path. A `://` anywhere in a url is read as its scheme's, and a secret elsewhere in a url, as in its query, is not looked for. In the scp form an @ in the path's first segment ends the userinfo, and so does an @ in the path of a url whose password holds a raw `/`, so the host, and the path ahead of that @, are left out too. A remote call killed at its bound prints none of what git said and leaves git's words in a file under `TMPDIR`. ssh's refusal names its user.
- **No verb writes the machine's install pointer alone (issue `0153`).** A publish to `install.prefix` writes it, and so does the publish-upgrade that rolls this release out; a `fleet` sweep refuses until one has, unless an exported `DEVBIN_INSTALL_PREFIX` names `install.prefix`, in which case it runs and warns that a shell without the variable will not find the install.
- **A manifest written before 0.1.9 keeps its recorded path through that project's first upgrade from a runtime older than 0.1.9 (issue `0153`)**, which runs that older runtime and records the path again; the upgrade after it, run by the new runtime, writes the kind of source, and `fleet upgrade --apply` makes both passes itself. Both old forms still resolve meanwhile. The `upgrade` page now says a second upgrade is needed (issue `0178`).
- **The machine's frozen list for `fleet` is declared nowhere yet (issue `0154`).** devbin's built-in list is empty, so a sweep plans an upgrade for every project the roots reach, archived ones included, until the machine declares `DEVBIN_FLEET_FROZEN`.
- **A project's own `.gitignore` in a gate's log directory is left as it is, even one that ignores nothing (issue `0157`)**, so that directory can still dirty the tree: where it is `tmp/release` the release pre-flight still refuses, and elsewhere the cut fails at step 5 once a gate writes there. Where git cannot say what a repository tracks, as of one it refuses to read, no ignore file is written and the run says so; one is written only where no `.git` sits at the project root or above it, as far up as git's own discovery looks (issue `0179`).
- **The cargo config order `check targetdir` and `fullcycle` read is cargo 1.99.0's as measured (issue `0164`)**: with both `.cargo/config` and `.cargo/config.toml` in one directory, cargo reads `config`. A build line run from outside the workspace does not read the workspace's config, so `fullcycle`'s offered `build.target-dir = "target"` does not reach it.
- **A `CARGO_TARGET_DIR` that resolves to `/` through `.`, `..` or a link reads "resolves to /, outside the project" rather than "is the filesystem root" (issue `0166`)**, and is refused all the same.
- **`check targetdir` does not see a cargo config inside a directory `find` cannot read at all, or deeper inside one it can search but not list (issue `0163`)**, nor a directory whose ACL denies only search, as 0.1.8 already said of every walk (issue `0145`). A workspace below the project root whose own config pins `target-dir = "target"` fails over an unreadable directory beneath it (at the project root that target is the shared tree, and it passes), since only what the directory hides tells a member from a second workspace; the failure says to make it readable or move it out of the workspace. Where `find` meets a directory it cannot read, `check targetdir` walks a second time, about 1.8 times one walk.
- **`clean` still never removes `<root>/target` for a nested crate with no root `Cargo.toml` (issue `0167`)**; `check targetdir` does not endorse that tree instead, since removing it would mean running cargo inside `clean`.
- **`fullcycle`'s artefact check does not see a release lost while another was built, the tree's own or a target triple's, and does not read custom profiles (issue `0168`).** A per-session directory built with `CARGO_CACHE_RUSTC_INFO=0`, or under a `build.build-dir` set to another directory, carries no `.rustc_info.json` and is read as a target triple.
- **cargo is asked from each crate's own directory (issue `0150`)**, so a build line that runs cargo from elsewhere, or passes `--target-dir` or `--config` itself, is not followed.
- **The lint arm skips where shellcheck is not installed, and reaches a change only in a run that includes `contract.bats` (issue `0155`).** An explicit empty `senders.*.dkim.type` is now refused, and no test holds that (issue `0161`).
- **A commented key in the reference config with prose directly above and below it reads as prose, so the schema check does not see it (issue `0173`).** None is written that way today.
- **Outside the `fleet` roots, an install whose `bin/.devbin/lib` cannot be searched passes the audit (issue `0175`)**, since that walk digests nothing; under the roots the audit still fails it.
- **The neutrality tests do not read a citation or a count split across two lines, other than a line ending in "issue" or one opening with an issue-shaped number, nor a line opening with `#` inside a heredoc or a multi-line string, nor a bare four-digit number, nor a count of machines (issue `0172`).** Each would be indistinguishable from innocent text in the tree; the test file declares them.
- **The `MIX_ENV=prod` refusal does not reach a project's own `db` handler (issue `0132`).**
- **The `fleet` census does not look inside `~/Library`, `~/.Trash` or anything reached only through a symlink (issue `0116`).**
- **The shipped pages are checked for prettier stability only where prettier is installed.**
- **`infra` checks DNS and mail records only.** The Fly runtime and `infra mail dmarc check` are devbin's ST0006, which is not built.
- **Intent and one other project still release with their own orchestrators.**
- **The release core's reads before the first push are not time-limited**, nor is `release status`.
- **A cut under `object: ci` depends on the project's workflow running.** If CI does not start a job, the tag and the pushes stand and the object step fails at `object_wait`.
