version: 0.1.17
date: 2026-10-29
headline: devbin's first public release installs over https with no credential, doctor prints the version line exactly as --version does, use and doctor's switch checks read PATH as a login shell does, and version set refuses an immutable file before it writes anything.
status: released

**Why this release exists.** It carries everything since 0.1.16: issues `0246` to `0250`, `0273`, `0275` to `0277` and `0279` to `0291`. It is the first release published as devbin's public repository, as one snapshot commit of the product (ST0010), so the install text, the formula's header and the fixtures say nothing that holds only while the repository is private (`0291`). It keeps a 0.1 number, as 0.1.8 to 0.1.16 did, because every consuming project pins a `^0.1` caret.

## Changed -- a script or a config may get a different result

- **doctor prints the version line unchanged, on a line of its own, as `--version` prints it (issue `0246`).** In devbin's own checkout it is doctor's first line, and the tree row says whether it names the checkout's commit. In a project, the install's line is printed alone, with what named that install on a detail row beneath it.
- **With no link left, a bare `use` and doctor's switch row report brew only when the first `devbin` on PATH is Homebrew's (issue `0273`)**, and otherwise fail, naming the copy that answers, or saying that none does.
- **`use dev` and `use opt` on a shadowed link leave it pointed, say so, and exit 1 (issue `0275`)**, naming what shadows it, with the remedy: fix PATH as that says, or run `use brew`.
- **The remedy for a machine with no Homebrew devbin is keyed by its cause, and said once (issue `0250`):** export `HOMEBREW_PREFIX` when it is unset or relative, install devbin with Homebrew under an absolute prefix that holds none, and `use dev` or `use opt` only from a dev or opt tree.
- **Where the commits cannot say which way an upgrade moves, the versions do (issue `0276`).** A source at a higher version reads as forward, a lower one as BEHIND, and equal versions still cannot tell. upgrade's direction lines name both versions where both read.
- **`version set` refuses an immutable file before it writes anything (issue `0279`):** `uchg` or `schg` on macOS, `i` on Linux, read in each platform's own spelling, so an immutable `Cargo.toml` sidecar no longer leaves the set half-written. Where the machine has no reader for the flag, the preflight says the file was not checked for it.
- **An install whose manifest cannot be read is refused naming the manifest (issue `0282`)**, never told to run `install`, which would make it a project.
- **`version check` words an empty sidecar in the one table's words, `holds nothing (expected <version>)` (issue `0289`)**, as `show` and `doctor` do.
- **`worktrees` reads every patch a bank carries (issue `0290`)**, so a staged diff matching a bank's second patch is matched to that bank, and the banks line counts the patches and names each bank that carries more than one.

## Fixed -- reaches every project

- **`use brew`'s lookup is the one a shell makes once the link is gone (issue `0247`)**: it passes over a `devbin` linked through the link, which would dangle, and reads the link's directory named in another case as the link's own, on a disk that folds case.
- **`use brew` counts a `devbin` on PATH only when it would run (issue `0249`)**, refuses naming a Homebrew devbin that is not executable, and answers off PATH only when Homebrew's bin is not searched.
- **`use brew` no longer names Homebrew's own link, typed in another case, as a copy to move aside (issue `0284`)**: the launcher and the hit are compared in the case the disk stores.
- **The shadow check searches only absolute PATH entries, and passes a first `devbin` whose chain of links reaches the link (issue `0285`)**, such as a `~/bin/devbin` made to `../.local/bin/devbin`.
- **doctor's switch row names a Homebrew keg by its opt link (issue `0287`)**, never a Cellar path the next `brew upgrade` removes.
- **An opt or brew tree whose manifest records a dirty source prints `<sha12>+dirty` on its version line (issue `0277`)**, not the bare commit.
- **The version is read from a `package.json` wherever its top-level `"version"` sits on its line, and from a `Cargo.toml` whose multi-line array holds lines opening with `[` (issues `0280`, `0281`)**, and `version set` rewrites that pair and no nested one.
- **devbin reads its own version from the manifest through the one reader of a manifest's fields (issue `0283`).**
- **PATH and `GIT_CEILING_DIRECTORIES` are split by one splitter, which keeps every entry (issue `0248`)**: an empty one, a trailing one and one holding a newline.
- **The README installs the tap and the formula over https with no credential (issue `0291`)**, and the docs and the formula's header no longer say the repository is private.

## Fixed -- devbin's own tree

- **`fullcycle`'s link walks stop at the shared bound, and the tests that count watched PATH links count them from their fixtures (issue `0286`).**
- **One helper writes a stub install for every test that needs one (issue `0288`).**
- **The test fixtures use reserved domains and documentation addresses throughout, the CI workflow and the release guide speak of runner cost without account detail, and the 0.1.0 note's `Known limitations` heading is restored (issue `0291`).**

## Known limitations

- **`worktrees` does not see a process of another user it cannot read (issue `0245`).**
- **The built-in `macos` has not yet signed or notarised a real app (issues `0226`, `0243`).** Its arms run against stand-ins for `security`, `codesign`, `xcrun`, `spctl` and `lsregister`.
- **CI green before the cut proves the base commit on the Tests workflow's summary (issue `0223`)**, and `release.ci.base` is refused under `release.publish.url`, where CI on the candidate is the gate.
- **On a forward move of the source, doctor's source row, the update notice and the offer compare the vendored set's bytes, which takes far longer than comparing commits (issue `0224`).** The notice asks at most once a day on a terminal.
- **`-only-testing` matches a type name, and devbin does not resolve a swift-testing display name to its type (issue `0229`)**; the empty-run refusal is where such a filter shows.
- **ST0008 is not finished, and devbin does not run natively on Windows.** AC-2.1's clause on WSL 2 behind a VPN is not yet measured, and AC-6.4, an adopting project running the smoke list in WSL, is not yet received. The WSL leg is a CI runner's WSL 2, and the smoke list's server is a stub.
- **The smoke list asserts the critic gate on the fixture carrying `intent/` by `check all`'s exit alone (ST0008 WP-06).**
- **A project's name has no shape, so no test holds the vendored set to naming none (issue `0202`)**; review holds it, and the workroom's names arm holds the owner's projects.
- **`text_shown` prints a url whose password holds a raw `/` (issue `0218`)**, a malformed url, as it stands.
- **An interceptor that forges AA is read as the zone's own answer, and the interception probe proves only what reaches TEST-NET-2 (issue `0193`).**
- **`infra` follows no CNAME (issue `0196`).**
- **Each remote has its own read-back in the push step, so a remote that does not answer holds a cut for over two minutes (issue `0194`).**
- **Install's line-ending block gives a project's newline-less last line a newline, and converts no file already carrying CR bytes (ST0008 WP-01).** doctor names each such file.
- **Some of devbin's own test files still build their fixtures per test (issue `0192`).**
- **`fullcycle.bats`'s slow-y arm reads a charged wait green when the time around the prompt passes a few seconds (issue `0199`)**, so under load it can miss a regression of `0096`.
- **`fullcycle`'s artefact check reads a `release/` it cannot list as holding no binary (issue `0177`)**; it fails closed, at rc 1.
- **Where git cannot say, whether a repository is there is read from the filesystem, and some cases read otherwise than git would (issues `0179`, `0185`).**
- **`vendor` does not refuse a devbin that is no checkout and has no manifest (issue `0178`)**; `upgrade` refuses one.
- **A check `check lint` runs again alone is not always alone, and nothing times a check out (issue `0184`).**
- **The release pre-flight still refuses a `tmp/` committed as a link outside the tree, and an untracked link on that path (issue `0186`).**
- **devbin's own `docs/authoring-commands.md` still recommends `postgresql://user:$PGPASSWORD@host/db`, and some arms plant the shape (issue `0187`)**; a vendoring project carries only the vendored set, which is clean.
- **A dry run's `no step failed` speaks for the steps it reaches (issue `0181`)**; the NOT REACHED list names the rest.
- **`release` leaves out of a url only what it can read as a userinfo (issues `0188`, `0189`).**
- **A manifest written before 0.1.9 keeps its recorded path through that project's first upgrade from a runtime older than 0.1.9 (issue `0153`).**
- **A project's own `.gitignore` in a gate's log directory is left as it is, even one that ignores nothing (issue `0157`).**
- **The cargo config order `check targetdir` and `fullcycle` read is cargo 1.99.0's as measured (issue `0164`).**
- **`check targetdir` does not see a cargo config inside a directory `find` cannot read (issues `0145`, `0163`)**, and a nested `clean` never removes `<root>/target` for a crate with no root `Cargo.toml` (issue `0167`).
- **`fullcycle`'s artefact check does not see a release lost while another was built, and does not read custom profiles (issue `0168`).**
- **cargo is asked from each crate's own directory (issue `0150`).**
- **The lint arm skips where shellcheck is not installed (issue `0155`)**, and no test holds the refusal of an explicit empty `senders.*.dkim.type` (issue `0161`).
- **A commented key in the reference config with prose directly above and below it reads as prose to the schema check (issue `0173`).**
- **The neutrality tests do not read a citation or a count split across two lines, nor a line opening with `#` inside a heredoc (issue `0172`).**
- **The `MIX_ENV=prod` refusal does not reach a project's own `db` handler (issue `0132`).**
- **The shipped pages are checked for prettier stability only where prettier is installed.**
- **`infra` checks DNS and mail records only.** The Fly runtime and `infra mail dmarc check` are devbin's ST0006, which is not built.
- **Intent and one other project still release with their own orchestrators.**
- **The vendored-set scans fold case in ASCII letters only (issue `0205`).**
- **The arm that holds a runtime to one digest under every locale runs where the runner has an en_US UTF-8 locale (issue `0204`).**
- **Assets reach a release after it is published, which works while immutable releases are off (ST0008 WP-08)**, and `release status` and `release attach` read a release's assets as consistent, not as complete.
- **An attach reads its assets from the run's artifacts, which GitHub keeps for a limited time, and each call to GitHub is cut off at a fixed bound (ST0008 WP-08).**
- **The release core's reads before the first push are not time-limited**, nor is `release status`.
- **A cut under `object: ci` depends on the project's workflow running.** If CI does not start a job, the tag and the pushes stand and the object step fails at `object_wait`.
